# 상단 메뉴바 정리와 명령 체계 통합 — 설계 · 계획

## Context

v1.12.0에서 네이티브 메뉴를 VS Code식 35px 커스텀 타이틀바로 바꿨다. 그 뒤로 기능이 늘 때마다 메뉴, 단축키, 명령 팔레트에 따로 덧붙였다. 그 결과 세 가지 문제가 생겼다.

- **명령 목록이 셋으로 갈라졌다.**
  - 정의가 세 곳에 있다. 메뉴는 `title-bar-menu.ts`, 단축키는 `keymap.ts`, 팔레트는 `app/quick-open-items.ts`다. 팔레트 명령은 손으로 적은 8개뿐이다.
  - 디스패처도 둘이다. `App.tsx:2179`의 `handleMenuAction`과 `App.tsx:1557`의 `handleQuickOpenSelect`다.
  - 그래서 Ctrl+Shift+P로 "확대"나 "세션 중지"를 찾을 수 없다. 거꾸로 프롬프트 라이브러리, 보류 메시지, 폴더 기록은 메뉴에 없다.
- **같은 기능의 진입점이 3~8곳이고 이름도 다르다.** 메뉴의 "폴더 추가"가 사이드바에서는 "폴더 열기"다.
- **메뉴에서 보이지 않는 기능이 있다.** 키 전용, 팔레트 전용, 트레이 전용 기능이다.
- **세션 메뉴의 대상이 섞여 있다.**
  - 새로고침은 `headerSession`, 제거는 `selectedSession`을 쓴다. 재개·중지는 기본값이 `selectedSession`이다.
  - 그런데 작업공간 화면에 들어갈 때(grid-actions.ts:219, 273)와 문서 패인에 포커스를 줄 때(App.tsx:939)는 `focusedPaneId`만 바뀐다.
  - 그래서 세션 메뉴가 포커스된 패인이 아닌 다른 세션에 작동할 수 있다. builder 점검 단계에서 코드로 확인했다.

**사용자 결정** (2026-11-06)
- 방향: 메뉴 단순화, 숨은 기능 발견성, 명령 체계 통합
- 편집 메뉴는 터미널 우클릭으로 옮긴다.
- 도구 메뉴는 세션 메뉴에 합친다.
- 메뉴바 바깥의 중복 진입점도 정리한다.
- Ctrl+P에서 명령을 뺀다. 명령은 Ctrl+Shift+P에서만 찾는다.

**참고 조사** (웹)
- VS Code: 모든 메뉴 항목이 명령이고, 팔레트에 단축키와 함께 나온다. → 이 방식을 채택한다.
- Cursor 2.x: 메뉴 옆에 둔 Agent/Editor 토글이 오클릭 불만을 샀다. → 메뉴 줄에 컨트롤을 추가하지 않는다.
- Orca: 팔레트를 용도별로 나눈다. Cmd-P는 파일, Cmd-J는 점프다. → Ctrl+P는 이동, Ctrl+Shift+P는 명령으로 나눈다.

## 목표 · 비목표 · 안티골

**목표**
1. 앱 명령 전부를 레지스트리 하나에 둔다. 메뉴, 팔레트, 설정 › 단축키가 이 레지스트리를 읽는다.
2. 메뉴는 4개다(파일·보기·세션·도움말). 설정 버튼은 그대로 둔다.
3. 레지스트리 명령은 모두 Ctrl+Shift+P에서 단축키와 함께 찾을 수 있다.
4. 같은 기능은 같은 이름을 쓰고, 같은 대상에 작동한다.
5. 메뉴바 바깥의 실제 중복을 줄인다.

**비목표**
- 타이틀바 배치와 모양은 바꾸지 않는다. 햄버거 메뉴, 레이아웃 토글, 톱니, 커맨드센터 재디자인이 여기에 든다.
- 폴더·워크트리·세션 우클릭 메뉴는 레지스트리로 옮기지 않는다.
- 트레이 메뉴는 그대로 둔다.
- i18n은 하지 않는다.

**안티골** (이렇게 되면 실패다)
- 리매핑할 수 있는 명령의 기존 id나 기본 단축키가 바뀐다. 그러면 사용자의 `appSettings.keybindings`가 깨진다.
- 터미널 안 프로그램이 받던 키를 새로 삼킨다.
- 팔레트에서 지금 실행할 수 없는 명령을 누를 수 있다.
- 우클릭 메뉴 때문에 터미널의 선택이나 붙여넣기 흐름이 나빠진다.

## 1. 명령 레지스트리

**정의**
- `keymap.ts`의 `KEYMAP_ACTIONS`를 명령 레지스트리로 넓힌다. 그대로 넓힐지 `commands.ts`로 옮길지는 builder가 정한다.
- 필드는 지금 것에 `palette`(팔레트 노출 여부)를 더한다. 지금 필드는 id, label, category, defaultAccelerator, fixed, terminalSafe, ignoreWhileTyping이다.
- **기존 id는 하나도 바꾸지 않는다.**
  - 지금 메뉴 전용 id도 그대로 레지스트리에 올린다. `tools.edit-agents`, `help.check-updates`, `file.add-folder`, `session.stop` 등이다.
- **새 id**는 지금 팔레트·트레이 전용이던 것과 새로 생기는 것만 만든다.
  - 홈 대시보드, 폴더 기록, 프롬프트 라이브러리, 보류 메시지 관리
  - 알림 끄기/켜기, 작업 영역 새로고침, 단축키 보기

**라벨**
- 명령마다 라벨은 하나다.
- 메뉴는 `label`만 보여 준다. 예: 세션 메뉴의 "중지"
- 팔레트와 단축키 설정은 `분류: label` 형식으로 보여 준다. 예: "세션: 중지". VS Code 방식이다.
- 분류는 메뉴 이름에 맞춘다(파일·보기·세션·도움말·편집 + 이동). 지금 라벨 "세션 새로고침", "터미널에서 찾기", "명령 검색"은 이 규칙에 따라 고친다. 라벨은 저장되는 값이 아니라서 바꿔도 안전하다.

**활성 판정과 메뉴 구성**
- `buildTitleBarMenus` 안에 있는 판정을 두 함수로 뽑는다. 메뉴와 팔레트가 같은 판정을 쓴다.
  - `commandEnabled(id, ctx)`: 지금 실행할 수 있는가
  - `commandLabel(id, ctx)`: 상태에 따라 바뀌는 라벨. 예: 사이드바 접기/펼치기, 알림 끄기/켜기
- 메뉴 정의는 id, 구분선, 하위 메뉴의 배치만 가진다.
  - `TitleBarEntry`/`TitleBarMenu` 타입은 유지한다. `TitleBar.tsx`는 하위 메뉴가 여러 개가 되는 것 말고는 거의 그대로다.

**팔레트**
- Ctrl+P(전체)에서는 `command` 행을 뺀다. 세션, 작업공간, 폴더, 프로젝트만 남는다. 자리표시 문구는 "세션·폴더 검색"이 된다.
- Ctrl+Shift+P와 '명령' 칩은 지금 켜진 레지스트리 명령을 보여 준다.
  - 꺼진 명령은 숨긴다.
  - 명령 모드에서는 10개 제한을 없애고 스크롤로 전부 보이게 한다.
  - 에이전트별 새 세션처럼 동적으로 생기는 명령은 지금처럼 붙인다.
- `QuickOpenItem`에 `shortcut`을 더한다. `QuickOpenPalette.tsx`가 행 오른쪽에 표시한다.

**디스패처와 설정**
- 디스패처는 `handleMenuAction` 하나로 합친다. `handleQuickOpenSelect`는 명령 행을 받으면 `handleMenuAction(id)`를 부른다.
- 설정 › 단축키 탭은 레지스트리 전체를 분류별로 보여 준다. 기본 단축키가 없는 명령에도 단축키를 지정할 수 있다.

**팔레트에서 빼는 명령**
- 복사·붙여넣기·모두 선택은 넣지 않는다. 팔레트가 포커스를 가져가 버린다.
- 슬롯 1~9 포커스, 패인 방향 이동, 페이지 넘김은 팔레트와 키로만 쓴다. 메뉴에는 넣지 않는다.

**재사용**
- keymap.ts: `effectiveAccelerator`·`resolveKeymap`·`findConflict`·`isBindableAccelerator`
- quick-open.ts: `rankQuickOpen`

## 2. 메뉴 최종안 (6개 → 4개)

```
파일   폴더 열기 · 업무 프로젝트 만들기
       ─ 파일 저장(Ctrl+S) · 폴더 다시 연결
       ─ 종료
보기   명령 팔레트(Ctrl+Shift+P) · 빠른 열기(Ctrl+P) · 홈 대시보드
       ─ 왼쪽 사이드바 접기/펼치기 · 오른쪽 사이드바 접기/펼치기 · 폴더 기록
       ─ 패인 확대/해제(Ctrl+Shift+Enter)
       ─ 화면 배율 ▸ 확대 · 축소 · 원래 크기   · 전체 화면(F11)
       ─ 파일 목록 새로고침(F5) · 작업 영역 새로고침
세션   새 세션 ▸ (에이전트들)
       ─ 다음 세션(Ctrl+Tab) · 이전 세션(Ctrl+Shift+Tab) · 다음 대기 세션(Ctrl+Shift+U)
       ─ 재개 · 새로고침 · 중지 · 제거
       ─ 프롬프트 라이브러리 · 보류 메시지 관리 · 알림 1시간 끄기 / 알림 다시 켜기
       ─ 에이전트 ▸ Claude 업데이트 · Codex 업데이트 · 에이전트 추가
도움말 업데이트 확인 · 릴리스 노트 · GitHub 저장소
       ─ 단축키 보기 (설정 › 단축키 탭)
       ─ 문제 해결 ▸ 다시 로드 · 개발자 도구(F12)
       ─ 버전 vX (비활성)
[설정]
```

- **편집 메뉴는 없앤다.** `edit.*` 명령은 레지스트리에 남고 고정 단축키도 그대로다. 우클릭 메뉴가 이 명령을 쓴다.
- **도구 메뉴는 세션 › 에이전트 ▸ 하위 메뉴가 된다.** `tools.*` id는 그대로 둔다.
- **알림 끄기/켜기**
  - 트레이의 `snoozeNotifications`(src/main/index.ts:198), 설정 › 알림 탭(SettingsDialog.tsx:1377-1394)과 같은 `notifications.snoozedUntil` 값을 쓴다.
  - 알림이 꺼져 있으면 라벨이 "알림 다시 켜기 (HH:MM까지 꺼짐)"이 된다.
- **←/→ 순환**은 메뉴 4개 사이를 돈다. 설정 버튼은 지금처럼 건너뛴다(TitleBar.tsx:115).

## 3. 터미널 우클릭 메뉴 (새로 만든다)

- 항목: 복사 · 붙여넣기 · 모두 선택 ─ 찾기 · 터미널 지우기
  - 복사는 선택된 글자가 있을 때만 켜진다.
  - 단축키 표시는 레지스트리에서 가져온다.
- **"모두 선택"은 단축키를 표시하지 않는다.** `edit.select-all`의 표시용 기본값을 null로 바꾼다.
  - 원래 Ctrl+A는 PTY로 가고 가로채지 않는다(TerminalPane.tsx:229-231). 지금 표기가 틀린 셈이다.
  - fixed 명령이라 사용자가 리매핑한 값이 없으니 안티골에 걸리지 않는다.
- **대상은 우클릭한 터미널이다.** 메뉴를 열 때 그 패인에 포커스를 준다(`focusPane`). 동작은 `terminalCommands.current.get(id)`를 그대로 쓴다.
- **구현 패턴**
  - `SessionContextMenu.tsx`와 `context-menu-position.ts`를 따른다.
  - 터미널 본문에만 붙인다. 패인 헤더 우클릭(세션 메뉴)은 그대로 둔다.
- **우클릭 동작**
  - TUI가 마우스 모드여도 우리 메뉴를 연다.
  - 우클릭하는 순간 xterm 선택이 풀리지 않게 한다. 복사가 선택을 읽어야 하기 때문이다.

## 4. 이름 · 대상 통일

**이름**
- 메뉴와 사이드바(ProjectSidebar.tsx:1354, 1364)에서 같은 이름을 쓴다. "폴더 열기"와 "업무 프로젝트 만들기"다.
- 사이드바의 "목록 새로고침"(ProjectSidebar.tsx:1344)은 "작업 영역 새로고침"으로 바꾼다. 레지스트리 명령으로도 등록한다.

**대상** (반드시 고친다)
- 세션 명령(재개·새로고침·중지·제거)은 **포커스 패인의 세션**에 작동한다.
  - 포커스 패인이 문서이거나 없으면 꺼진다.
- 새 세션(메뉴·팔레트)은 헤더 런처와 같은 규칙을 쓴다.
  - 폴더 화면: 선택된 폴더와 worktree
  - 작업공간 화면: 포커스 패인의 폴더와 worktree
  - 헤더 런처가 대상을 고르는 로직(session-actions.ts:173-186 부근)을 재사용한다. 지금 팔레트는 worktree를 빠뜨린다(App.tsx:1590). 이것도 함께 고친다.
- `session.refresh`는 포커스 세션 하나만 새로 그린다. 워크스페이스 헤더의 "화면 새로고침"(보이는 패인 전부)은 그대로 둔다.

## 5. 메뉴바 바깥 중복 정리

| 대상 | 처리 | 이유 |
|---|---|---|
| 워크스페이스 헤더 🗑 (포커스 세션 제거) | 없앤다 | 모든 터미널 패인 헤더에 🗑가 있다(PaneHeader.tsx:318, WorkspaceGrid.tsx:344-380) |
| 워크스페이스 헤더 📁 (폴더 다시 연결) | 없앤다 | 폴더가 사라지면 안내 줄에 "다시 연결"이 이미 뜬다(App.tsx:2438-2450). 메뉴와 폴더 우클릭에도 있다 |
| 사이드바 하단 업데이트 배지 | 할 일이 있을 때만 보인다(확인 중·다운로드 중·재시작 필요·실패) | 평소의 "최신" 표시와 버전은 도움말 메뉴와 겹친다 |
| 수동 업데이트 확인 결과 "최신" | 토스트로 알린다(`toast.tsx`) | 배지가 숨으면 결과가 보이지 않는다 |
| 새 세션 진입점 8곳 | 남기고 라벨만 맞춘다 | 각각 다른 대상을 가진 문맥 진입점이다 |
| 팔레트에 손으로 적은 명령 8개 | 레지스트리에서 자동으로 만든다 | §1 |
| 트레이 메뉴 | 남긴다 | 창이 숨어 있을 때 유일한 경로다 |

## 구현 순서

작업은 main 브랜치에서 직접 한다. 워크트리와 구현자 서브에이전트는 쓰지 않는다. 메모리에 적힌 규칙이다.

1. **설계 문서 저장**: 이 문서를 `docs/superpowers/specs/2026-11-06-title-bar-command-registry-design.md`로 저장하고 커밋한다.
2. **레지스트리**
   - `keymap.ts`를 레지스트리로 넓히고 `commandEnabled`·`commandLabel`을 둔다.
   - 기존 id와 기본값을 고정하는 테스트를 먼저 쓴다.
3. **메뉴 재구성**
   - `title-bar-menu.ts`를 id 배치 중심으로 다시 쓴다.
   - `App.tsx`의 `handleMenuAction`에 새 id를 넣는다.
   - 세션 명령의 대상을 포커스 패인 기준으로 고친다(§4).
4. **팔레트**
   - `quick-open-items.ts`의 명령 행을 레지스트리에서 만들고, Ctrl+P(전체)에서는 뺀다.
   - 단축키 표시와 명령 모드의 개수 제한 해제를 넣는다.
   - `handleQuickOpenSelect`를 합친다.
5. **설정 › 단축키 탭**: 레지스트리 전체를 분류별로 보여 준다.
