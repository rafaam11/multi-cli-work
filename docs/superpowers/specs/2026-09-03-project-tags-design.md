# 업무 프로젝트 태그와 "태그로 묶어 보기"

## 문제

사이드바 트리는 v1.27.0부터 `채널 › 업무 프로젝트 › 폴더` 3단인데, 맨 위의 "채널" 층은 ws-root
워크스페이스(`C:\work\<채널>\<셸>`)를 등록한 사용자에게만, 폴더 이름에서 자동으로 유도되어 생긴다.
사용자가 직접 만들거나 바꿀 수 없고, 워크스페이스 밖의 업무 프로젝트는 묶을 방법이 없다. 게다가
그 워크스페이스 체계는 채널 물리 계층을 폐기하고 관심사 태그(Topic)와 책임 경계(Context)로 옮겨
갈 예정이라, 앱이 채널 폴더 규약에 묶여 있으면 그 변화를 따라갈 때마다 앱을 고쳐야 한다.

multi-cli-work는 범용 도구다. 사용자의 워크스페이스 모델(finite/continuous, PRJ 키, PROJECT.yaml)에
종속되는 개념은 앱에 넣지 않는다. 필요한 것은 "프로젝트 위에 사용자가 마음대로 두는 얇은 상위 층"
하나뿐이고, 그 층을 데이터로 강제하지 않는 것이 요구다.

## 결정

**태그만 두고, "묶어 보기"는 뷰 옵션으로 한다.**

- 업무 프로젝트에 자유 문자열 태그를 여러 개 붙인다. 계층도 권한도 없다.
- 사이드바의 **묶기** 드롭다운에서 태그를 여러 개, 순서 있게 고르면 트리가 `태그 묶음 › 업무
  프로젝트 › 폴더`로 그려진다. 고르지 않으면 지금까지처럼 평면이다.
- ws-root 채널은 **동기화 때 채널 라벨을 태그로 한 번 심어 주는 소스**로 격하한다. 채널 전용 트리
  코드는 일반 태그 묶음 노드로 대체된다.
- 태그는 **별도 파일** `~/.multi-cli-work/project-tags.json`에 산다. `work-projects.json` 스키마와
  `WorkProject` 타입은 바뀌지 않는다(레지스트리 계약 §8 — 구버전은 모르는 파일을 무시하므로
  다운그레이드가 안전하다).

## 동작

### 태그

- 업무 프로젝트 상세 페이지의 **태그** 칸: 칩(✕로 제거) + 입력. 입력은 `Enter` 또는 `,`로 커밋하고,
  한글 조합 중(`isComposing`)의 Enter는 조합 확정이므로 무시한다. 빈 입력에서 `Backspace`는 마지막
  칩을 뺀다. 자동완성 후보는 다른 업무 프로젝트가 이미 쓰는 태그(많이 쓰인 순, 동률 이름순).
- 정규화: 앞뒤 공백 제거 → 빈 값 제거 → 32자 절단 → 중복 제거(대소문자 구분, 첫 등장 순서 유지).
  파서·저장·편집기가 같은 함수를 쓰므로 손으로 고친 파일도 앱과 같은 답을 낸다.
- 색은 이름의 FNV-1a 해시로 7색 팔레트에서 고른다. 색은 뜻이 아니라 구별 표시다. 팔레트는
  기존 구분(category) 색 계열을 다시 쓴다 — 한 화면에 색 계열이 둘이면 색이 뜻하는 바가 흐려진다.
- 저장은 즉시다(칩 커밋은 이산적인 행동이라 디바운스가 필요 없다). 저장 실패는 상세 페이지의
  기존 저장 오류 배너에 뜬다.

### 묶어 보기

- 트리 컨트롤 줄(모두 / 접기 / 작업중) 오른쪽의 **묶기** 버튼: `묶기: 개인 › 용역` 또는 `묶기: 없음`.
  누르면 메뉴(`menuitemcheckbox`)에 존재하는 태그가 나열되고, 고르면 **끝에 붙고** 해제하면 빠진다
  — 순서는 고른 순서다. 맨 아래 **묶기 해제**. 순서 재배치(↑↓)는 만들지 않는다: 해제 후 다시
  고르면 된다.
- 트리: 업무 프로젝트는 고른 순서대로 훑어 **첫 번째로 일치하는 태그** 묶음 아래 한 번만 선다.
  묶음은 그 묶음의 첫 구성원이 있던 자리를 차지한다(정렬해 둔 순서가 통째로 뒤집히지 않는다 —
  채널 묶음이 하던 규칙 그대로). 어느 태그에도 걸리지 않으면 **나머지** 묶음 아래이고 나머지는 항상
  마지막이다(키 `tag:`; 이름을 `기타`로 두지 않는 이유는 ws-root 채널 라벨 태그 `기타`와 같은 이름의
  묶음이 나란히 서기 때문이다 — 2026-09-03 개정). 미분류(어느 업무 프로젝트에도 안 든 폴더)는 묶음 밖
  최상위, 나머지보다 뒤 — 미분류는 폴더 이야기고 나머지는 업무 프로젝트 이야기라 섞지 않는다.
- 묶음 노드는 채널 노드처럼 접고 펼친다. 접힘 키는 `tag:<이름>`(기타는 `tag:`)이고 사이드바의
  `expandedWorkspaces`에 저장된다. 모두 / 접기 / 작업중은 묶음 층까지 다룬다("작업중"은 돌아가는
  폴더를 가진 묶음만 남긴다).
- 묶기 선택은 `multi-cli-work.sidebar.v1`에 `groupingTags` 키로 저장한다(버전 1 유지). **키가
  없으면 "저장된 선호 없음"**이고, 그때는 기본값이 돈다: ws-root 셸이 하나라도 있으면 실제로 붙어
  있는 채널 라벨 태그들을 고정 순서(과제·용역·연구·기타·개인)로, 없으면 빈 묶기(평면). 기본값은
  렌더마다 파생하는 값이라 저장하지 않으며, 사용자가 한 번 고르면 그때부터 저장된 값이 이긴다.
  업그레이드 직후 화면이 채널 층이 있던 때와 같게 보이는 것은 이 기본값 덕이다.

### ws-root 동기화

- `workspace:sync`가 셸에서 업무 프로젝트를 upsert할 때, `project-tags.json`에 그 업무 프로젝트의
  **행이 아직 없으면** 채널 라벨(`WorkspaceShellInfo.channelLabel`: 과제·용역·연구·기타·개인)을
  태그로 심는다. 행이 있으면(빈 배열이라도) 손대지 않는다 — 행의 존재가 "사용자가 한 번은
  태그를 손댔다"는 표식이다. 그래서 파서·저장·정리 어디서도 **빈 배열 행을 지우지 않는다**.
  이 규칙 하나가 새 프로젝트 생성과 업그레이드 백필을 함께 덮고, 구분(category)이 "만들 때
  한 번만" 정해지는 것과 같은 문장으로 설명된다.
- 사라진 업무 프로젝트의 행은 동기화 때 버린다. 심을 것도 버릴 것도 없으면 파일에 손대지 않는다.

### 노출

- 트리의 업무 프로젝트 행: 이름 뒤에 태그 칩 최대 3개 + `+N`(나머지는 툴팁). 행 버튼의 접근성
  이름(`aria-label`)은 그대로다.
- 홈 대시보드 카드: 구분 칩 옆에 같은 칩.
- 빠른 열기(`Ctrl+P`): 업무 프로젝트가 항목으로 들어가고 `detail`에 `#태그 #태그`가 실리므로
  `#연구`로도 `연구`로도 찾힌다. 고르면 그 업무 프로젝트 상세 페이지가 열린다.
- SessionStart 브리프의 업무 프로젝트 절에 `- 태그: a, b` 줄(태그가 없으면 줄 생략).

## 저장

`~/.multi-cli-work/project-tags.json` v1:

```json
{ "schemaVersion": 1, "updatedAt": "2026-09-03T00:00:00.000Z", "tags": { "<workProjectId>": ["개인", "AI"] } }
```

- 최상위만 exact-keys(`schemaVersion`·`updatedAt`·`tags`). `tags`는 열린 레코드다.
- 잠금·원자적 쓰기·`.bak`·복구는 다른 레지스트리와 같은 `json-store` 프로토콜(계약 §4~§6).
- 사라진 업무 프로젝트의 행은 읽을 때 무시하고 동기화 때 정리한다.
- 경로는 `MULTI_CLI_WORK_PROJECT_TAGS_PATH` 환경변수로 바꿀 수 있다(테스트·e2e 격리).

## 하지 않는 것

- 태그 색 사용자 지정, 묶기 순서 재배치(↑↓), 폴더(SharedProject) 단위 태그.
- `work-projects.json`·`projects.json`·`state.json`에 필드 추가. 옛 `channel:*` 접힘 키의 마이그레이션.
- 구분(category) 필드의 변경이나 태그로의 통합.
- 워크스페이스 모델의 도메인 개념(finite/continuous, PRJ 키, PROJECT.yaml) 반영.

## 테스트 전략

- 순수 함수(정규화·조회·해시·트리 묶음·기본 묶기)는 단위 테스트로 계약을 못 박는다.
- 레지스트리는 임시 디렉터리 fs 테스트(왕복·exact-keys 거부·정규화·빈 배열 행 유지·prune·`.bak` 폴백).
- 동기화는 네 상황(신규 프로젝트, 업그레이드 백필, 사용자가 지운 `[]` 행, 사라진 행 정리)을 고정한다.
- 통합(App): 채널 묶음 테스트를 태그 묶음으로 재작성하고, 묶기 메뉴·재시작 유지·업그레이드
  기본값·행 칩·빠른 열기를 추가한다. e2e는 채널을 참조하지 않으므로 수정이 없다.

## 부록 (2026-09-03): 폴더 아래 세션·문서 행과 worktree 층 복원

v1.27.0이 세션 행을 트리에서 빼고 하단 패널로 옮긴 결정에 대한 사용자 피드백: "폴더 아래에 세션이
보이던 예전이 편했다. 숫자만 남으니 어색하다." v1.28.0이 그 패널을 작업공간 셸프와 합쳐 트리 **위**로
올린 지금, 트리에 세션 행을 되살려도 두 목록의 역할이 겹치지 않는다 — 위는 "지금 화면에 모은 것",
아래는 "어느 폴더의 것"이다.

- 폴더 아래에 그 폴더의 세션·문서 행이 선다. 폴더는 다시 접고 펼치며, 이미 그리드가 떠 있는 폴더를
  다시 누르면 접힌다(v1.26 그대로). 접힘은 일부러 지우지 않았던 옛 키 `multi-cli-work.projects.v1`에
  저장되므로 업그레이드 전 배치가 그대로 돌아온다.
- worktree가 **하나라도** 있는 폴더는 `메인 · branch` / `⎇ branch` 층으로 나뉘어 각자 자기 세션·문서를
  품는다. worktree가 없으면 그 층 없이 세션이 폴더 바로 아래에 선다.
- 상단 세션(작업공간) 패널은 그대로다. 접근성 이름만 v1.26의 구분으로 돌아간다: 트리 행은
  `세션 열기`/`문서 열기`/`닫기`, 패널 행은 `패인 열기` — 한 화면에 같은 이름이 둘이면 테스트가
  전부 흔들린다.
- 폴더 상세 페이지의 워크트리 카드는 그대로 남는다(트리 행 우클릭과 같은 메뉴).
