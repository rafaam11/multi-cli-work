# 사이드바 3단 트리와 세션 패널

## 문제

ws-root 워크스페이스(`C:\work` 아래 `<채널>/<셸>`, 루트 CLAUDE.md의 채널-프로젝트 체계)를 등록하면
사이드바는 `채널 › 업무 프로젝트(셸) › 폴더 › (worktree ›) 세션`을 그린다 — 4~5단이다. 채널 층은
`5e6c2ef`에서 얹혔고, 그 아래는 그 전부터 있던 `업무 프로젝트 › 폴더 › 세션`이다. 층이 하나 늘면서
트리가 너무 깊어졌다.

세션 행을 트리에서 빼는 것은 이미 한 번 해 봤다. `b1dc9ee`가 뺐고 `2560114`가 되돌렸다. 되돌린 이유는
"패인 탭 바는 지금 보는 뷰만 말하니 **다른 폴더가 뭘 들고 있는지** 아무것도 알려주지 않았고, 문서는
흔적조차 없었다"였다. 즉 트리 속 세션 행의 진짜 가치는 지금 보고 있지 않은 폴더의 세션이 어떤 상태인지
한눈에 보는 것이다. 그 가치를 지키면서 트리를 얕게 만들어야 한다.

## 결정

1. 트리는 **채널 › 프로젝트 › 폴더** 딱 3단이다. 폴더가 잎이다.
2. **세션 행은 트리에서 나온다.** 사이드바 하단에 평면 **세션 패널**이 생기고, 기본 범위는 전체다.
   트리는 "어디에 뭐가 있나"(장소)를, 세션 패널은 "지금 무엇이 나를 기다리나"(상태)를 답한다.
   두 질문을 두 영역이 나눠 맡으므로 트리가 얕아져도 교차 폴더 가시성은 남는다.
3. **worktree도 트리에서 나온다.** worktree 세션은 세션 패널 행에 `⎇ 브랜치`를 달고 서고, worktree
   관리(열기·컨텍스트 메뉴·만들기)는 폴더 상세 페이지의 워크트리 카드로 옮긴다.

순수 렌더러 변경이다. 레지스트리·IPC·메인 프로세스·`workspace.json`·`.ws-index.json` 스키마는
건드리지 않는다.

## 동작

### 사이드바 레이아웃 (펼친 상태)

```
[홈] 멀티 터미널 작업기
▸ 작업공간  5                        ← 셸프 두 개, 그대로
▸ 숨김      2
프로젝트 ──────────────── ↻ 💼 📁
 [모두] [접기] [작업중]               ← 채널+프로젝트 층에 작용
▾ O_SMCH  용역                       ← 채널: 접기/펼치기만 (그대로)
  ▾ 가상병원 VSP                      ← 프로젝트(업무 프로젝트=셸): 클릭=상세 페이지
      vsp-client        ● 3          ← 폴더: 잎, 체버론 없음, 클릭=그리드
      vsp-server          1
손으로 만든 묶음 / 미분류             ← 셸이 아닌 업무 프로젝트: 최상위 유지
세션  대기 2  [전체 | 여기]  ▾        ← 신규 패널, 접기 가능
  ● multi-cli-work ⎇ fix/updater · 로그   승인 대기
  ● vsp-client · 렌더러 수정              입력 대기
  ○ llmwiki · 인덱스                      작업 중
  ○ 도구 · claude 업데이트
  📄 multi-cli-work · README.md      ✕   ← 문서 패인은 세션 뒤
폴더 5개 / 세션 7개
```

접힌 레일(44px)은 폴더 버튼 목록 그대로다. 세션 패널은 접힌 레일에 마운트하지 않는다.

### 폴더 행 — 잎

- 체버론이 없고 `aria-expanded`도 없다. 클릭하면 그 폴더의 그리드가 열린다. 이미 그리드가 떠 있는
  폴더를 다시 클릭하면 아무 일도 일어나지 않는다 — 접을 것이 없기 때문이다. "이미 보는 행을 다시
  누르면 접힌다"(`8257fdd`)는 프로젝트 행에만 남는다.
- 남는 것: 드래그 정렬과 그룹 이동, 우클릭 메뉴, 탭에서 가리킬 때의 깜빡임, Teams/GitHub 브랜드
  아이콘, 폴더 없음 표시, 오른쪽 레일의 주의 점(승인 대기가 입력 대기보다 세다)과 세션 수 배지.
  세션 수는 지금처럼 worktree 세션을 포함한다.
- worktree를 보고 있을 때는 그 worktree가 속한 폴더 행이 `selected`로 남는다.

### 세션 패널

**무엇이 서는가.** 모든 세션과 모든 문서 패인. 폴더가 없는 도구 세션(CLI 업데이트)도 여기 선다 —
지금의 "도구" 그룹은 없어진다. 도구 세션은 `shelfPaneRows`가 이미 쓰는 규칙대로 소속이 "도구"다.

**순서.** 등급 오름차순 → 같은 등급 안에서 `updatedAt` 내림차순 → `id` 오름차순(안정).

| 등급 | 대상 |
|---|---|
| 0 | `awaiting-approval`, 또는 화면 밖에서 시작된 승인 대기(`unread` = approval) |
| 1 | `awaiting-input`, 또는 화면 밖에서 시작된 입력 대기(`unread` = input) |
| 2 | `working`, `starting` |
| 3 | `idle`, `exited`, `error` |
| 5 | 문서 패인 — 언제나 세션 뒤, 열린 순서 그대로 |

상태와 `unread` 중 강한 쪽을 쓴다. 화면 밖에서 시작된 대기는 상태가 이미 지나갔을 수 있어서다.
`applyEvent`는 `updatedAt`을 건드리지 않으므로, 목록은 등급이 바뀔 때만 움직이고 목록 새로고침 때만
2차 키가 흔들린다. 등급 변화로 행이 위로 튀는 것은 이 패널의 목적 그 자체다.

**행.** 트리의 세션 행과 같은 행이다 — 상태 점, 에이전트 아이콘, 이름, 읽지 않음 점, 상태 글자.
거기에 소속이 붙는다: `{폴더명}[ ⎇ {브랜치}] · {세션 라벨}`. 문서는 `{소유 폴더명}[ ⎇ 브랜치] · {문서
라벨}`이고 닫기 ✕가 있다. **접근성 이름은 바뀌지 않는다** — `{세션 라벨} 세션 열기[ (읽지 않음)]`,
`{문서 라벨} 문서 열기`, `{문서 라벨} 닫기`. 소속과 브랜치는 눈에 보이는 별도 span과 `title`에만 들어간다.
스크린 리더에 소속이 안 읽히는 것은 알고 받아들인 트레이드오프다: 이 이름을 그대로 두어야 세션 행을
찾는 기존 테스트 여덟 곳과 e2e 헬퍼가 그대로 산다. 소속을 접근성 이름에 넣는 것은 별도 작업이다.

행이 하는 일은 트리에 있을 때와 같다: 클릭하면 그 세션의 그리드로 간다(worktree 세션이면 worktree
그리드), 우클릭 메뉴, 인라인 이름 바꾸기, 작업공간·숨김·그리드 슬롯으로 드래그, 초점 행과 화면에
있는 행의 강조.

**범위.** 헤더의 `전체 | 여기` 토글. 기본은 전체다. "여기"가 가리키는 곳:

| 화면 | 여기 |
|---|---|
| worktree 그리드 | 그 worktree의 세션과 문서 |
| 폴더 그리드 / 폴더 상세 | 그 폴더의 세션과 문서 — **worktree 세션 포함**(폴더 배지와 같은 정의) |
| 업무 프로젝트 상세 | 그 프로젝트에 속한 폴더들의 세션과 문서 |
| 홈, 작업공간/숨김 셸프, 채널 | 범위 없음 — "여기" 버튼이 비활성이고 전체가 보인다. 저장된 선호는 지우지 않는다 |

도구 세션은 폴더가 없으므로 어떤 "여기"에도 들지 않는다. 범위 안에 아무것도 없으면 `{범위 이름}에 열린
세션이 없습니다`가 선다. 전체를 보고 있을 때, 또는 범위 대상이 없을 때(위 표의 "범위 없음")는 폴더
이름을 대지 않고 그냥 일반형 `열린 세션이 없습니다`라고만 말한다.

**헤더.** 제목 "세션", `대기 N` 배지(승인·입력 대기의 합 — **접혀 있어도 보인다**, 그래야 접어 둘 수
있다), 범위 토글, 접기 버튼. 접힘과 범위 선호는 `multi-cli-work.sidebar.v1`에 `sessionPanelOpen`,
`sessionScope` 키로 저장한다. 읽는 쪽이 결측 키에 관대하므로 버전은 올리지 않는다.

**크기.** `max-height: min(40vh, 340px)`에 자체 스크롤. 스플리터는 만들지 않는다.

### worktree — 폴더 상세 페이지의 워크트리 카드

폴더 상세 페이지(`ProjectDetailPage`)에는 worktree **목록이 없었다**. `worktree` prop은 페이지 자신이
어느 worktree에 스코프됐는지만 말한다. "Git 상태" 카드 뒤에 **워크트리 카드**가 선다.

- 문구와 접근성 이름은 `FolderStartPage`의 워크트리 카드를 따른다: `{브랜치} 워크트리 열기`, 보고
  있는 것은 `{브랜치} (보는 중)`이고 열기가 비활성, 헤더에 `워크트리 만들기`.
- 행에 `변경 N · 세션 N`, PR 리뷰 중이면 `PR #n · 임시`, locked/missing/prunable 표시. 정렬은 트리에
  있을 때와 같다 — PR 리뷰가 붙은 것을 뒤로, 나머지는 브랜치 이름순.
- 우클릭하면 지금의 worktree 컨텍스트 메뉴(새 세션·탐색기·에디터·변경 보기·fetch·unlock·정리·제거·PR)가
  뜬다. 메뉴는 **행 래퍼에** 건다 — 보는 중인 행은 버튼이 비활성이라 버튼에 걸면 우클릭이 죽는다.
- 이 카드는 worktree에 스코프된 페이지에서도 보인다. 형제 worktree로 옮겨 가는 것이 카드의 절반이고,
  보고 있는 worktree를 우클릭해 정리하는 것이 나머지 절반이다.
- 트리 아래에 서던 worktree 경고(`worktreeWarnings[project.id]`)도 이 카드로 옮긴다.
- 폴더 그리드 안에서 worktree 세션 패인에 초점을 주면(`focusPane`, 기존 동작) 앱이 그 worktree로 다시
  스코프된다 — 세션 패널의 "여기"도 그만큼 좁아진다. e2e가 이 카드를 쓰기 전에 폴더를 다시 여는 것은
  이 때문이다.

worktree를 **여는** 길은 셋이 남는다: 이 카드, `FolderStartPage`의 워크트리 카드(패인이 없을 때만),
우측 git 탭의 worktree 드롭다운. 컨텍스트 메뉴만 이 카드 하나로 유일해진다.

### 트리 컨트롤 — 모두 / 접기 / 작업중

폴더 층이 접히지 않으므로 세 버튼은 채널과 프로젝트 층에만 작용한다. "작업중"은 `isFolderActive`인
폴더를 가진 프로젝트와 그 채널만 펼치고 나머지는 접는다. 프로젝트 접힘은 App이, 채널 접힘은 사이드바가
갖고 있으므로(`expandedWorkspaces`, 키가 있으면 접힘) 사이드바가 App 콜백을 부른 뒤 채널 키를 함께
갱신한다. `expandedWorkspaces`에 남아 있던 `worktree:*`·`main:*` 키는 아무도 읽지 않으므로 무해하다.

## 구조

| 파일 | 역할 |
|---|---|
| `src/renderer/src/session-panel.ts` | 순수 함수. 세션·문서 → `SessionPanelItem[]`(소속·브랜치·등급 포함, 정렬 완료), 범위 판정, 대기 수 |
| `src/renderer/src/SessionPanel.tsx` | 표시 전용. 헤더 + 평면 목록. 트리의 세션·문서 행 마크업을 그대로 물려받는다 |
| `src/renderer/src/sidebar-tree.ts` | 순수 함수. 트리 묶음(`treeSections`/`treeNodes`)과 "작업중"이 접을 채널 키 계산 |
| `src/renderer/src/ProjectSidebar.tsx` | 세션·문서·worktree·도구 그룹이 빠지고, 폴더가 잎이 되고, 세션 패널을 장착한다 |
| `src/renderer/src/App.tsx` | 폴더 접힘 상태가 사라지고, 세션 패널 항목과 범위 대상을 만들고, worktree 메뉴 진입을 상세 페이지로 옮긴다 |
| `src/renderer/src/ProjectDetailPage.tsx` | 워크트리 카드 |
| `src/renderer/src/index.css` | 패널·카드 스타일. 죽은 worktree 트리 스타일 제거 |

App이 항목을 만들어 정렬까지 끝내 넘기고, 사이드바는 그리기만 한다 — `shelfPaneRows`와 같은 이유다.
`shelfPaneRows`와 라벨 계산이 겹치지만 매핑 방향이 반대(셸프는 슬롯 순서를 유지해야 한다)라 이번에는
합치지 않는다.

## 하지 않는 것

- 세션 패널의 스플리터. 접기와 `max-height`로 충분하다.
- 접근성 이름에 소속 넣기. 기존 테스트·e2e와의 호환이 우선이고, 별도 작업으로 뺀다.
- `shelfPaneRows`와 `sessionPanelItems`의 통합.
- 셸프(작업공간/숨김) 코드의 분리. 이번 변경의 대상이 아니다.
- `COLLAPSED_PROJECTS_KEY`(`multi-cli-work.projects.v1`) localStorage 값 삭제. 읽지도 쓰지도 않되
  지우지도 않는다 — 다운그레이드하면 그 배치가 그대로 살아 있다.

## 테스트 전략

- `session-panel.ts`·`sidebar-tree.ts`는 단위 테스트로 계약을 못 박는다(정렬 등급, `unread` 승격,
  tie-break, 문서 후순위, 소속/브랜치 라벨, 문서 소유자 역참조, 범위 판정).
- `App.test.tsx`의 세션 행 쿼리(`{라벨} 세션 열기`)와 `getByRole("button", { name: "PowerShell 세션
  열기" })` 정확 일치 + 클래스 단언은 **그대로 통과해야 한다** — 마크업 보존의 리트머스다.
- worktree 트리 행·폴더 접힘에 묶인 테스트는 재작성한다. e2e의 worktree 스모크 시나리오는 상세 페이지
  워크트리 카드 경로로 옮긴다.
- Playwright e2e(빌드 포함)는 워크트리에서도 돈다 — node-pty의 Electron 재빌드(postinstall)가 실패해도
  prebuilt 바이너리로 충분하다(2026-09-02 스모크 9/9·전체 18/18 확인). 손으로 앱을 띄워 보는 확인은
  머지 후 main 체크아웃에서 한다.
