# MCW v2.0.0 implementation ledger and release contract

Source of intent: the user's approved Herdr transition and v1.55.1 rollback plan, 2026-10-30.
Latest steering (2026-10-30): complete all functionality and non-Android verification, then deploy. The user explicitly excludes Android verification from this release gate; disclose that deferral in the release. Android implementation and distribution remain in scope.

## Required behavior

- Keep project → repository → path/worktree → session navigation, project materials, notes and Git tools.
- Each task gets a new lead; user chooses Claude Code/Codex profiles for lead and up to three workers. Unspecified worker host defaults to the lead host. Workers communicate, submit evidence and leave changes unintegrated for user decisions.
- An independent mcw-host on each PC owns durable tasks, attempts, executions, messages and results and an authenticated phone gateway. GUI exit does not stop work. Restart recovery is distinct from process survival.
- Pinned, hash-verified Herdr 0.9.5 in dedicated mcw-v2 session, API commands and event subscriptions; per-session tab and root pane. Small Rust protocol bridge, shared desktop/Android Canvas renderer, explicit terminal size owner; observers do not resize.
- SSH connects PCs; phones connect directly to authenticated host gateways. Lead PC owns task, disconnects do not rerun or elect a new lead; remote results persist until delivery.
- Lead uses a dedicated brief directory. Writing workers use MCW-owned worktrees. Verify remote checkout and base commit; no automatic reset/fetch/merge/push.
- Distinguish execution, question/approval waiting, delivery, submitted result and user acknowledgement. Idle is not complete. Disconnection displays observation time. Acknowledge only the waiting event actually viewed.
- Remove v2 jk CLI/MCP, aliases, bundles, installers, env/config injection. Task-only MCP: inspect/assign/message/wait/submit/cancel. Display chips use bounded Herdr metadata independent of lifecycle. Preserve historical boards, conversations and user prompts; flag edited presets for migration. Preserve v1/v2 mod versions separately.
- Before v2 runtime starts, verify a consistent immutable backup of stopped v1 userData (including Local Storage), ~/.multi-cli-work, remote and mod state; path/size/hash manifest. Separate v2 userData and registry. Journal shared config before/after hashes; do not overwrite later edits.
- Bundle ORIGINAL v1.55.1 installers and digests per platform; stage recovery executable and assets outside replaceable install folder for offline/startup-failure recovery.
- Rollback stops new work, requires known stopped/completed work across hosts or explicit user stop, preserves v2 state and results, gracefully stops GUI/host and checks residual instances. Restore v1 data, original installer, conflict-safe shared configs. Disable update check, session auto resume and repo sync in restored working copy; clear pending v2 updater state. Verify installed version/data then launch. Never rewind Git or provider transcripts. Reupgrade reuses v2 and reports v1 differences without merging.
- Android keeps newest versionCode and pairing, supports host v1/v2; never require APK downgrade.
- Stable/latest untouched by previews. Publish v2.0.0 after Windows/Linux terminal and cooperation tests and Windows/deb/AppImage offline rollback round trips pass. Android verification is explicitly deferred by the user's later release instruction; disclose the gap without recording a pass.

## Work breakdown / completion gates

1. Terminal protocol bridge, API/event client and Canvas proof, Windows/Linux tests; defer physical Android to last.
2. Host/task domain, durable collaboration, attempt/generation authority, disconnect recovery, task MCP.
3. App/remote UI and feature migration; no jk v2 runtime dependencies, preserve historical v1 assets.
4. Backup, recovery runner, assets and roundtrip tests, safe restored defaults, Android dual host mode.
5. Full non-Android checks and independent review, package roundtrips, gated release with the Android verification deferral disclosed.

## Rulings / interface checks

- User plan is the binding spec; no separate spec file exists.
- Terminal → host: JSON messages over stdio from Rust bridge, session-scoped binary endpoint frames; never infer execution from a rendered idle screen.
- Domain → gateway/UI: shared v2 domain types and durable store; each action carries task/attempt/run generation.
- Recovery → bootstrap: bootstrap must complete backup before loading modules with registry path constants; no production-data writes during development tests.
- Release → validation: package version remains 1.55.1 until v2 release conditions are met. Preview builds must not advertise stable/latest.
- Ruling: switch to subagent-driven implementation for independent recovery/domain modules after source inventory exposed clean boundaries; integration and final acceptance remain on the root agent.
