# v1.29.0 — 업무 프로젝트 태그와 구분 설정

업무 프로젝트에 자유 태그를 붙이고 사이드바를 태그로 묶어 볼 수 있다. 구분(카테고리)은 앱에
박힌 어휘 대신 설정 창에서 직접 정의한다. 좌측 트리에는 폴더 아래 세션·문서 행과 worktree 층이
돌아왔다.

## 변경 사항

- 업무 프로젝트 상세 페이지에서 태그를 붙이고 뗀다. 다른 프로젝트가 쓰는 태그가 자동완성으로 뜨고 저장은 즉시다
- 사이드바 "묶기" 메뉴에서 태그를 고르면 고른 순서대로 묶이고, 어느 태그에도 없는 프로젝트는 `나머지` 아래에 선다. 묶기를 해제하면 평면 목록이다
- ws-root 워크스페이스 셸에서 만들어진 업무 프로젝트는 채널 라벨을 태그로 한 번 받는다. 업그레이드 직후에는 채널 라벨 묶기가 `(자동)`으로 켜져 이전 채널 트리와 같은 모양이다
- 트리 행과 홈 카드에 태그 칩이 붙고, 빠른 열기(`Ctrl+P`)에서 `#태그`로 업무 프로젝트를 찾는다
- Claude 세션 브리프에 `- 태그:` 줄이 들어간다
- 구분을 설정에서 직접 만든다. 설정 › 프로젝트 탭에서 이름·색(7색)·순서·기본 구분을 편집하며, 기본 목록은 업무·개인·연구·기타다
- 새 업무 프로젝트와 ws-root 셸에서 생기는 프로젝트는 설정의 기본 구분을 받는다. 채널 글자→구분 매핑은 없어졌고 채널 정보는 태그로만 남는다
- 세션 패널 헤더의 남는 폭 전체(대기 배지 포함)를 눌러 작업공간을 연다 — 숨김 행과 같은 규칙이다
- 좌측 트리의 폴더 아래에 세션·문서 행이 다시 보인다. worktree가 있는 폴더는 `메인 · branch` / `⎇ branch` 층으로 나뉘고, 없으면 그 층 없이 바로 세션 행이다. 상단 세션 패널은 그대로다
- 폴더를 열면 저장된 접힘도 풀린다 — 재시작 뒤 마지막으로 보던 폴더의 세션 줄이 접혀 있지 않다

## 업그레이드 시 보이는 변화

- v1.28 이전에 만든 `정부지원과제`·`외주개발`·`상품개발` 구분의 프로젝트는 새 기본 목록에 없어 회색으로 보인다. 값은 그대로고 상세 페이지의 구분 select에 현재 값으로 남는다. 설정 › 프로젝트에서 같은 이름을 추가하거나 프로젝트마다 새 구분을 고르면 색을 되찾는다
- `기타`는 지금까지와 같은 회색이다
- 태그는 `~/.multi-cli-work/project-tags.json`에 따로 산다. 구버전은 이 파일을 모르고 무시하므로 다운그레이드해도 프로젝트 목록은 안전하다
- 구버전으로 되돌리면 `settings.json`의 구분 목록이 지워질 수 있다(모르는 필드를 버리는 파일). 업무 프로젝트에 저장된 구분 값 자체는 무관하다
