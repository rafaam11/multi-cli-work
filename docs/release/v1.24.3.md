# v1.24.3 — 업무 프로젝트의 노션 링크·참고 폴더 라벨이 재시작 후 되돌아가던 문제 수정

업무 프로젝트 상세 페이지에서 노션 링크 라벨을 `노션` → `삼성서울병원_채널` 처럼 바꾸면 화면에는
새 라벨이 남지만, 앱을 다시 켜면 옛 라벨로 돌아와 있던 문제를 고쳤다. 같은 코드 패턴을 쓰던
`참고 로컬 폴더`의 라벨·경로 입력도 함께 고쳤다.

## 변경 사항

- **입력값이 저장되는 기준을 blur 이벤트에서 값 자체로 바꿨다.** 기존에는 입력 행이 포커스를
  잃는 순간 그 렌더의 클로저에 잡힌 배열로만 저장을 시도했고, 저장 전 비교에서 "변경 없음"으로
  판단되면 조용히 건너뛰었다. 한글 IME는 조합 중 포커스가 빠지면 확정된 글자를 `blur` **뒤에**
  흘려보내기 때문에, blur 시점의 값에는 방금 친 라벨이 없었다 — 저장은 스킵되고 state만 갱신되어
  화면에는 새 라벨, 디스크에는 옛 라벨이 남았다
- 이제 화면의 값이 저장된 값과 달라지면 400ms 뒤 자동 저장하며, 행이 포커스를 잃거나 페이지가
  교체될 때는 기다리지 않고 즉시 기록한다. 라벨을 치던 도중 사이드바에서 다른 항목을 눌러
  페이지가 blur 없이 통째로 교체되는 경로도 언마운트 시점에 저장된다
- 참고 폴더 선택 다이얼로그는 행의 포커스를 가져가 blur가 발생하지 않는데, 자동 저장이 값 기준으로
  동작하므로 고른 경로가 그대로 저장된다(기존 동작 유지)
- URL이 비어 있는 노션 링크 초안 행은 여전히 저장을 유발하지 않는다(기존 동작 유지)

## 호환성

- 렌더러의 입력 저장 시점만 바뀐 수정으로, 저장 스키마·IPC·메인 프로세스 동작 변경은 없다
- 라벨을 비운 채 저장하면 노션 링크는 `노션`, 참고 폴더는 폴더 이름이 기본 라벨로 채워지는
  기존 규칙은 그대로다
- **이미 `노션`으로 저장돼 버린 기존 링크의 원래 라벨은 이 수정으로 복원되지 않는다.** 입력값이
  디스크에 도달한 적이 없어 어디에도 남아 있지 않으므로, 해당 링크는 한 번 다시 입력해야 한다

## 검증

- 회귀 테스트를 먼저 작성해 재현했다: `compositionStart → blur → change → compositionEnd`
  순서(IME 확정 입력이 blur보다 늦게 도착)와 blur 없는 언마운트, 두 경로 모두 수정 전에는
  저장이 나가지 않음을 확인한 뒤 수정했다. 노션 링크는 이번에 처음으로 테스트가 붙었다
- Vitest 전체 통과 (95개 파일 988테스트)
- `npm run typecheck` 통과
- 릴리스 CI가 Windows 2022와 Ubuntu 22.04 x64에서 전체 Electron E2E와 패키징을 재검증한다
