# v1.55.3 — 세션 화면 재생 안정화

다른 앱에서 돌아올 때, 레이아웃이 바뀔 때, 앱을 다시 켤 때 세션 대화의 간격이 깨지던 문제를 겨냥한 패치입니다. 세션 구조는 그대로 두고 출력을 다시 재생하는 데 필요한 정보를 보강했습니다.

- **크기 기록 재생**: 출력이 어떤 크기로 쓰였는지 로그에 함께 기록하고, 다시 붙을 때 그 크기를 순서대로 따라가며 재생합니다. 데스크톱과 모바일 화면에 모두 적용합니다.
- **긴 로그의 터미널 모드 보존**: 5MB 한도로 앞부분이 잘려도 대체 화면·bracketed paste·focus report 같은 모드와 마지막 크기를 복원합니다. 재생이 제어 시퀀스 중간에서 시작하지 않습니다.
- **복원 이력 유실 수정**: 재시작 후 복원한 이력이 한 덩어리로 링 버퍼에 들어가, 한도를 넘는 순간 통째로 버려지던 문제를 고쳤습니다.
- **창 복귀 다시 그리기**: 다른 앱에서 돌아오면 보이는 패인을 다시 맞춥니다. 크기가 그대로면 같은 크기로 다시 그리도록 요청하고, 바뀌었으면 크기를 조절합니다.
- **재개 시작 크기**: 수동 재개는 해당 패인 크기로, 화면에서 시작하는 세션은 측정 가능한 현재 패인 크기로, 패인 없는 자동 재개는 로그의 마지막 크기로 시작합니다. 화면도 크기 이력도 없는 경우와 배경 시작은 기존처럼 80x24입니다.
- **덮어쓰기 출력 압축**: 스피너처럼 같은 줄을 계속 덮어쓰는 출력이 복원 한도를 소모하지 않도록 합칩니다. 크기가 알려져 있고 줄바꿈이 없는 연속된 같은 행 덮어쓰기만 대상이며, 전체 화면 TUI 프레임은 압축하지 않습니다.
- **출력 필터 교체**: 화면 지우기 시퀀스를 삭제하던 필터를 없애고 xterm의 `scrollOnEraseInDisplay`를 사용합니다. 읽던 위치와 이력을 유지하면서 이전 화면은 정상적으로 지웁니다.
- **폰의 크기 소유권 보존**: 창 포커스 보고(`ESC[I`/`ESC[O`)는 PTY에 전달하되 사람의 입력으로 치지 않습니다. 크기가 변하지 않은 재측정도 폰의 크기를 되찾지 않습니다. 실제 패인 크기 변경, 사람의 입력, 명시적인 되찾기는 기존처럼 데스크톱으로 돌려받습니다.
- **재개 구분선 순서**: 새 PTY 출력이 구분선보다 먼저 로그에 들어갈 수 있던 순서를 고쳤습니다. 실패한 시작에는 구분선을 남기지 않습니다.
- **ConPTY 진단 수단**: Windows 기본값은 내장 ConPTY로 유지합니다. 이 PC의 합성 측정에서 번들 DLL은 일반 버퍼 줄 누락이 없었지만, 망가진 대체 화면을 같은 크기 resize로 복구하지 못했습니다. 비교용으로 `MULTI_CLI_WORK_CONPTY=bundled`와 `scripts/probe-terminal-backends.cjs`를 추가했습니다.

**호환성**: 세션 로그에 사설 OSC 크기 기록(`ESC ] 7719 ; cols ; rows BEL`)이 추가됩니다. xterm은 이 기록을 화면에 그리지 않습니다. 저장 형식을 바꾸는 마이그레이션은 없습니다.

**한계**: 다음은 이 버전에서 해결되지 않았거나 확인하지 못한 부분입니다.

- 실제 Claude Code 대화에서 원래 증상이 사라졌는지는 확인하지 못했습니다. 합성 TUI와 실제 ConPTY·xterm, 격리된 앱으로 메커니즘을 검증한 결과입니다.
- 창 복귀 때 깨지는 직접 원인은 찾지 못했습니다. 창 복귀 다시 그리기는 원인 수정이 아니라 완화책입니다.
- 크기 기록은 이 버전이 받은 출력부터 쌓입니다. 기록이 없는 기존 로그는 예전처럼 재생됩니다.
- 출력이 나오는 중에 크기를 바꾸면 내장 ConPTY가 일반 버퍼에서 줄을 잃을 수 있습니다(합성 측정에서 240줄 중 19~21줄).
- 패인보다 넓은 폭으로 끝난 종료 세션의 대체 화면은 잘려 보입니다. PTY가 없어 다시 그릴 수 없습니다.
- 폰이 크기를 가진 상태에서 데스크톱 화면을 새로고침할 때 패인 측정값이 달라지면 크기가 데스크톱으로 돌아옵니다. Linux CI에서 50x44가 51x44로 바뀌는 것을 관측했고, 측정값이 바뀌는 원인은 찾지 못했습니다. 폰에서 '폰 크기로'를 다시 켜면 복구됩니다.
- windows-2022 CI 러너의 내장 ConPTY는 xterm이 보낸 bracketed paste 표식을 프로그램에 전달하기 전에 지웁니다. 글자는 도착하지만 표식이 없어 프로그램은 붙여넣기를 일반 입력으로 받습니다. 로컬 Windows 11(26200)에서는 표식이 전달되고, 다른 Windows 버전은 확인하지 못했습니다.

**검증**: Windows에서 Vitest 245개 파일·2,467개 테스트, 타입 검사, 프로덕션 빌드를 통과했습니다. 격리된 Electron 앱에서 실제 ConPTY·xterm으로 `terminal-replay`·`mobile` E2E 6개를 통과했습니다. 전체 E2E는 로컬에서 실행하지 않았고, 패키징된 앱에서 직접 확인하지도 않았습니다. 릴리스 CI에서 Windows·Linux 전체 테스트와 E2E·패키징을 다시 수행합니다.
