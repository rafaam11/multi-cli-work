# v1.41.0 — 패인 확대, 대기 세션 점프, 워크트리 스크립트, 사용량 게이지 (v1.38.1~v1.40.0 포함)

Orca·cmux·Ghostty를 살펴보고 가져온 기능들이다. 여러 에이전트를 한 화면에 띄워 두고 오가는 일, 워크트리를 만들어 바로 일을 맡기는 일, 한도를 미리 아는 일이 빨라진다.

**v1.38.0 다음 공개 버전은 이것 하나다.** v1.38.1~v1.40.0은 따로 배포하지 않고 이 릴리스에 함께 담았다. 각 묶음의 자세한 내용은 해당 노트에 있다.

- [v1.38.1](v1.38.1.md) — **고친 것**
  - 터미널에 포커스가 있으면 Ctrl+Tab·Ctrl+1~9가 먹지 않던 문제를 고쳤다.
  - Codex 세션이 진행 신호(OSC 9;4)를 받으면 "입력 대기"로 잘못 바뀌던 문제를 고쳤다.
  - 폰·원격 창 키 줄에 ←·→를 넣었다.
- [v1.39.0](v1.39.0.md) — **터미널**
  - 패인 확대(`Ctrl+Shift+Enter`)와 방향 이동(`Ctrl+Alt+방향키`)
  - 다음 대기 세션(`Ctrl+Shift+U`, 타이틀바 표시 클릭)
  - 터미널에 찍힌 파일 경로 `Ctrl+클릭` — VS Code나 앱 안에서 그 줄로 연다
  - 패인 머리줄 밑 진행선과 작업 중 표시, 작업표시줄 진행률
- [v1.40.0](v1.40.0.md) — **에이전트 흐름**
  - 폴더별 워크트리 준비·정리 스크립트
  - 변경 비교 화면의 줄 메모를 같은 체크아웃 세션에 보내기
  - `jk status`·`jk progress`로 패인 머리줄에 상태 칩·진행률 걸기
  - 앱 안 터미널에서 띄운 개발판의 `jk`가 거절되던 문제를 고쳤다
- **v1.41.0(이 문서)** — 타이틀바의 Claude·Codex 구독 사용량 링 게이지, 그리고 90% 알림.
  - **`jk`가 UTF-8이 아닌 Windows에서 동작하지 않던 문제를 고쳤다.** 앱이 설치하는 `jk-coding-cli.ps1`에 BOM이 없어서, Windows PowerShell 5.1이 시스템 코드 페이지(CP949, 영문 Windows의 1252 등)로 읽었다. 그러면 스크립트의 한글이 깨져 문법 오류로 끝났다. 시스템 로캘에서 "UTF-8 사용(베타)"을 켠 PC에서만 정상이었다. 이제 BOM을 붙여 쓴다.

폰 앱(0.2.0)은 바뀌지 않았다. 폰 화면의 ←·→는 호스트 PC가 이 버전이면 바로 보인다.

## v1.41.0 — 타이틀바 구독 사용량 게이지

Claude와 Codex의 5시간·주간 한도를 타이틀바에서 본다. 한도에 부딪혀 프롬프트가 튕기기 전에 안다.

### 바뀐 것

- **사용량 링**
  - 타이틀바 가운데, 빠른 열기 옆에 공급자마다 한도 창별 작은 링이 뜬다.
  - 색은 60% 미만 초록, 85% 미만 호박색, 그 이상 빨강이다. 빨강일 때는 천천히 숨 쉬듯 깜박인다.
  - 값이 바뀌면 링이 부드럽게 차오른다. 마우스를 올리면 "Claude 5시간 42% · 주간 81%"처럼 읽힌다.
- **팝오버**
  - 링을 누르면 공급자별로 창마다 막대, 퍼센트, 초기화까지 남은 시간("2시간 13분 후 초기화"), 플랜, 몇 분 전 값인지가 나온다.
  - 열 때마다 새로 읽는다. 1분에 한 번까지다.
- **90% 알림**: 5시간이나 주간 한도가 90%를 넘으면 그 창이 초기화될 때까지 한 번 데스크톱 알림을 띄운다.
- **설정 › 알림 › 구독 사용량**: 게이지와 90% 알림을 각각 끈다.

### 어디서 읽나

- **Claude**
  - `~/.claude/.credentials.json`(또는 `CLAUDE_CONFIG_DIR`)의 로그인 토큰으로 Anthropic 사용량 API(`api.anthropic.com/api/oauth/usage`)를 읽는다. Claude Code의 `/usage`와 claude-hud가 쓰는 것과 같은 곳이다.
  - 토큰은 요청할 때마다 새로 읽고 그 요청의 헤더에만 쓴다. 저장하거나 로그에 남기지 않는다.
  - 앱 시작 때 한 번 읽고, 이후에는 Claude 세션이 돌고 있는 동안 5분마다 읽는다.
  - 실패하면 15초부터 5분까지 늘려 가며 다시 시도한다. 429는 서버가 말한 시간만큼 기다린다.
  - API 키로 쓰거나 `ANTHROPIC_BASE_URL`로 다른 게이트웨이를 쓰면 읽지 않는다.
- **Codex**
  - 가장 최근 세션 기록(`~/.codex/sessions/…/rollout-*.jsonl`, 또는 `CODEX_HOME`)의 끝부분에서 마지막 `token_count` 이벤트가 담은 한도를 읽는다.
  - 서버에 묻지 않으니 값은 마지막 Codex 턴 시점의 것이다. 팝오버의 "N분 전 갱신"이 그 시점이다.
  - 앱 밖에서 쓴 Codex도 반영된다.
- **저장**: 마지막으로 읽은 값은 `userData/usage-snapshot.json`에 남겨, 다음 시작 직후에도 게이지가 보인다. 토큰은 담지 않는다.

### 알아둘 것

- Claude 사용량 API는 공개 문서에 없는 주소다. 응답 형식이 바뀌면 Claude 게이지만 조용히 사라지고 나머지 동작에는 영향이 없다.
- 새 외부 통신이 생겼다: `api.anthropic.com`(Claude 사용량). 설정에서 게이지를 끄면 이 요청도 멈춘다.
- 플랜에 따라 Codex는 주간 창 하나만 줄 수 있다. 이 경우 링도 하나다.

### 검증

- 단위 테스트를 통과했다(전체 1,972개). 새로 붙인 것:
  - 자격 증명 읽기, 사용량 응답 파싱(형식 불일치면 null), 요청 헤더, Retry-After
  - Codex 한도 파싱(5시간·주간 구분, `resets_at`·`resets_in_seconds`), 최신 rollout 찾기, 끝부분만 읽기
  - 갱신 주기(5분, Claude 세션 조건, 1분 제한), 재시도, 90% 알림 한 번, 꺼짐, 저장값 복원
  - 게이지 색 구간·초기화/갱신 문구, 링·팝오버 렌더
- TypeScript 검사와 프로덕션 빌드를 통과했다.
- Electron E2E `desktop.spec.ts`(27개): 임시 Codex 기록(5시간 91%, 주간 40%)으로 타이틀바에 링 2개가 뜨고, 첫 링이 빨강이며, 팝오버에 플랜과 초기화 시간이 나오는 것을 확인했다. 모든 E2E는 Claude 자격 증명 경로를 임시 폴더로 바꿔 실제 API를 부르지 않는다.
- 이 PC의 실제 Codex 기록으로 파서를 돌려 주간 한도·초기화 시각·플랜이 맞게 읽히는 것을 확인했다.
