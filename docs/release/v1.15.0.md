# v1.15.0 — 가장자리 스냅 + 헤더로 올라간 레이아웃 줄 + 작업공간 드롭 수정

## 변경 사항

- **패인을 가장자리로 던져 배치한다.** 패인 헤더나 탭을 그리드의 **위 가장자리**로 끌면 전체 화면, **좌·우 가장자리**는 2칸의 그 절반, **네 모서리**는 2×2의 그 사분면이 된다. Windows의 창 스냅과 같은 조작이고, 결과도 레이아웃 타일에서 손으로 고를 수 있는 배치 그대로다 — 스냅은 "그 영역을 슬롯으로 그리는 프리셋으로 바꾸고 그 슬롯에 패인을 넣는" 한 동작으로 표현된다. 끄는 동안에는 대상 영역만 반투명으로 미리 보이고 **실제 배치는 놓는 순간 한 번만** 바뀐다(패인 크기가 바뀔 때마다 xterm→PTY resize가 연쇄로 도는 것을 막는 기존 원칙 그대로). 그리드 안쪽으로 끌면 지금까지처럼 슬롯끼리 자리를 바꾼다
- **레이아웃 줄이 그리드 위에서 사라지고 헤더 줄로 들어갔다.** 대기·폴더·상세·런처 버튼 **왼쪽**에 타일 한 줄로 붙는다. 헤더 높이는 그대로라 그 줄만큼 **터미널이 세로로 커진다**. 칸 수 제목과 구분선은 없앴고, 창이 좁아지면 자동 이름 → 타일 크기 순으로 줄어든다(스크롤은 만들지 않는다 — 스크롤해야 닿는 피커는 아낀 높이보다 비싸다)
- **레이아웃 프리셋을 15개에서 8개로 줄였다.** 자동 + 전체(1칸) · 좌우(2칸) · 메인+우측 2 · 3열(3칸) · 2×2 · 3열+우측 2분할(4칸) · 메인+우측 2×2(5칸) · 3×2(6칸). **두 패인은 항상 좌우로만** 나눈다 — 상하로 쌓으면 터미널이 가장 아쉬워하는 줄 수가 양쪽 다 절반이 된다. 자동의 5칸 배치는 사라진 `5-thirds-split` 대신 `5-main-quad`를 쓴다(칸 모양은 같고 첫 열만 넓어진다). 없어진 프리셋으로 저장돼 있던 뷰는 **칸 수에 맞는 대체 프리셋으로 열린다**
- **버그 수정 — 폴더에서 작업공간으로 끌어다 놓아도 담기지 않던 문제.** 드래그가 `effectAllowed = "move"` 로 시작하는데 작업공간 행은 `dropEffect = "copy"` 를 요구했다. HTML5 드래그 앤 드롭은 이 조합을 비호환으로 보고 드롭을 **취소**하므로 `drop` 이벤트가 아예 발생하지 않았다 — 같은 payload를 쓰면서 `"move"` 를 요구하는 그리드 슬롯만 멀쩡했던 이유다. 슬롯 드롭은 이동, 작업공간 드롭은 참조 복사라는 두 의미를 모두 살리도록 `copyMove` 로 고쳤다
- **버그 수정 — 우측 사이드바에서 연 파일이 좌측 트리에도 나타나던 문제.** 문서는 이제 **탭 바와 그리드에서만** 다룬다. 트리는 작업공간 · 업무 프로젝트 · 폴더 · worktree까지이고, 세션과 마찬가지로 문서도 행을 만들지 않는다. 파일 닫기는 파일 패인의 **파일 닫기** 버튼 그대로다
- **세션 제거 버튼이 눈에 보이는 곳으로 나왔다.** 패인 헤더의 **✕(슬롯 비우기)** 옆에 **🗑(세션 제거)**, 그리고 상단 헤더 오른쪽 끝에도 같은 버튼이 붙는다. 헤더 쪽은 **포커스된 패인** 기준이라 여러 폴더의 패인이 섞이는 작업공간에서도 무엇을 지우는지 이름으로 밝힌다. 확인 다이얼로그와 우클릭 → 제거는 그대로다

## 테스트 하네스 수정

- E2E에서 창 크기를 900×600으로 줄이는 **압축 레이아웃 테스트가 크기를 되돌리지 않아**, 이후 모든 테스트가 몇 줄짜리 터미널에서 돌고 있었다. 긴 프롬프트 위에 찍힌 마커가 렌더된 행 밖으로 밀려나 **창 크기 문제가 그때그때 다른 assertion의 실패로 위장**됐다. 해당 테스트가 끝나면 기본 크기(1280×820)로 되돌린다
- 탭→작업공간 드롭 E2E 헬퍼는 합성 `DragEvent` 를 직접 dispatch하느라 브라우저의 effect 협상을 건너뛰었다. 위 드롭 버그를 통과시킨 원인이라, 이제 `effectAllowed` 와 `dropEffect` 의 호환성을 검사해 어긋나면 실패한다
