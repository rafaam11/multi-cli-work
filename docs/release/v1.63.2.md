# v1.63.2 — 큰 단위 Linear 프로젝트에서 PRJ 찾기

세컨드브레인 역할 재정리(2026-11-23)에서 Linear 프로젝트 구조를 바꿨습니다. 이제 PRJ마다 프로젝트를 하나씩 두지 않고, 큰 단위 4개(회사·세컨드브레인·진로·박사·우리·생활)로 묶습니다. 각 프로젝트 본문 첫 줄에는 그 프로젝트가 담는 PRJ 키를 `projectKey: PRJ-0017, PRJ-0013`처럼 적습니다.

v1.63.0·v1.63.1은 이름이 `PRJ-####`로 시작하는 프로젝트만 찾았습니다. 그래서 바뀐 구조에서는 브리프에 Linear 절이 나오지 않았습니다(오류 없이 빠짐).

- **세션 브리프 › Linear 맥락**
  - 찾는 방법을 두 단계로 바꿨습니다.
    1. 프로젝트 목록을 가볍게 받아, 본문 첫 줄의 `projectKey:` 목록에 폴더의 PRJ 키가 있는 프로젝트를 고릅니다. 짧은 설명 칸에 적힌 경우와 옛 이름 방식(`PRJ-0017 …`)도 이어서 봅니다.
    2. 고른 프로젝트의 열린 이슈와 최근 댓글을 가져옵니다.
  - 머리줄은 `## Linear 맥락 (PRJ-0017 · 세컨드브레인 · 조회 …)`처럼 PRJ 키를 앞에 붙입니다.
  - 새 이슈를 만들 때 라벨 `repo:<레포>`와 `by:mcw-<cli>`를 붙이라고 안내합니다. Linear 팀이 쓰는 레포·작성자 라벨입니다.

**호환성**
- 저장 형식·설정·IPC는 바뀌지 않았습니다.
- 이름이 `PRJ-####`로 시작하는 옛 프로젝트도 계속 찾습니다.

**검증**
- Windows에서 타입 검사와 Vitest 256개 파일·2,625개 테스트를 통과했습니다.
- 앱이 쓰는 두 쿼리를 실제 Linear에 그대로 보내 봤습니다. `PRJ-0017`과 `PRJ-0013`이 모두 `세컨드브레인` 프로젝트로 찾아지고, 열린 이슈 10개가 `repo:` 라벨과 함께 들어옵니다.
- 태그를 찍기 전에 main CI에서 Ubuntu 테스트, Windows 2022·Ubuntu 22.04 desktop Electron E2E, Android 셸 빌드를 확인합니다.
