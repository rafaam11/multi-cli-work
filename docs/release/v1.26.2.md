# v1.26.2 — WMI가 멈춘 PC에서도 업데이트 설치가 끝까지 간다

**확인**은 되는데 재시작해도 버전이 그대로였다면, 원인은 이거였다: electron-builder의 NSIS 설치
프로그램은 "앱이 아직 실행 중인가"를 PowerShell `Get-CimInstance`(안 되면 `tasklist` — 이것도
내부적으로 WMI를 거친다)로 물어보는데, 그 호출에 타임아웃이 없다. Windows의 WMI 서비스(Winmgmt)가
멈춘 PC에서는 이 첫 번째 질문에서 설치 프로그램이 **영원히 블록**된다. 자동 업데이트는 이 설치
프로그램을 무음(`/S`)으로 띄우고 앱을 곧장 종료하므로, 창도 오류도 없이 그냥 조용히 실패한 것처럼
보인다 — 실은 멈춰 있을 뿐이다. 다운로드는 정상, sha512도 일치, 그저 설치가 시작도 못 한 것.

## 변경 사항

- **설치·제거 시 "실행 중인가" 확인이 WMI를 전혀 안 쓴다.** 대신 `CreateToolhelp32Snapshot` 기반
  `nsProcess` 플러그인을 쓴다 — WMI 서비스 상태와 무관하게 동작한다. 동작은 그대로다: 먼저 정상
  종료를 요청하고, 5초 안에 안 닫히면 강제 종료한다
- **그래도 안 닫히면(예: 앱이 관리자 권한으로 떠 있는데 설치 프로그램은 아닌 경우) 조용히
  넘어가지 않고 멈춘다.** 잠긴 실행 파일을 덮어써서 설치가 반쯤 깨지는 것보다는, "닫을 수 없습니다"
  안내와 함께 확실히 멈추는 쪽을 택했다
- **업데이트 로그가 남는다** (`userData/logs/updater.log`, 512KB에서 한 번 순환). 무음 설치는
  실패해도 창이 없어 신호가 없었는데, 이제 다음에 같은 문제가 생기면 로그로 바로 원인을 알 수
  있다. 오류는 스택 트레이스까지 남는다

## 알아둘 점

- 이 수정은 **새로 빌드된** 설치 프로그램·제거 프로그램에만 적용된다. 1.26.1 이전 버전에서 이
  버전으로 올라오는 **딱 한 번의 업데이트**는, electron-builder가 구버전을 지우려고 그 구버전에
  번들된(수정 전) 제거 프로그램을 그대로 실행하는 단계가 있어 그 순간엔 옛 WMI 검사를 한 번 더
  거친다 — 그 시점에 WMI가 멈춰 있으면 거기서 한 번 더 걸릴 수 있다. **이 버전이 설치된 뒤부터는**
  설치·제거 양쪽 다 수정판이라 이 문제 자체가 다시 생기지 않는다
- `nsProcess`는 실행 파일 이름으로만 찾고 설치 경로로 거르지 않는다(플러그인 자체의 한계 — 기존
  `tasklist` 대체 경로도 같은 한계였다). 이론적으로 서로 다른 경로에 설치한 두 인스턴스가 있으면
  한쪽 설치가 다른 쪽 실행 중인 인스턴스를 닫을 수 있다. WMI 무한 대기보다는 낫다고 보고 받아들였다

## 검증

- Vitest 전체 통과 (104파일 1121테스트, 이전 1120에서 1개 추가 — 스택 트레이스 없는 Error 폴백
  케이스)
- TypeScript typecheck 및 프로덕션 빌드 통과
- **WMI가 실제로 멈춘 PC에서 재현·검증했다.** `Get-CimInstance`/`tasklist`가 45초 넘게 응답하지
  않는 환경에서, 수정 전 빌드는 설치 프로그램이 18분 이상(CPU 0.5초) 블록되는 것을 확인했고, 수정
  후 빌드는 같은 환경에서 12~14초 만에 실행 중인 앱을 종료하고 설치를 마쳤다
  (`--updated /S --force-run` — electron-updater가 실제로 넘기는 인자 그대로)
- 커스텀 NSIS 매크로가 실제로 호출되는지 마커 파일로 직접 확인(컴파일 성공만으로는 포함 여부를
  보장하지 않는다는 것을 두 차례의 잘못된 빌드로 확인한 뒤)
- 강제 종료까지 실패하는 경우의 안전 중단 경로는 코드 리뷰로 짚여 이번에 추가됐다(별도 실행 검증은
  없음 — 관리자 권한 프로세스를 인위적으로 재현하지 않았다)
