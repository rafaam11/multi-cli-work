# v2.0.1 — Windows 설치본에서 세션이 열리지 않던 문제 수정

v2.0.0 Windows 설치 파일로 설치하면 PowerShell·Claude Code·Codex 세션이 모두 `Operation rejected`로 열리지 않았습니다. 이번 업데이트로 고쳤습니다.

- **원인**: 설치 파일을 만드는 7-Zip이 Herdr의 ARM64용 ConPTY 실행 파일(`conpty/arm64/OpenConsole.exe`)을 새 ARM64 필터로 압축했습니다. NSIS 설치기는 이 필터를 읽지 못해 오류 없이 이 파일만 건너뛰었습니다. Herdr는 첫 터미널을 열 때 구성 파일 목록을 검사하다 멈췄고, 호스트는 이후 모든 세션 요청을 거부했습니다.
- **수정**: 설치 파일은 설치기가 해제할 수 있는 압축 방식만 씁니다. 출시 빌드는 설치 파일 안의 모든 파일이 실제로 설치 가능한지, Herdr 구성 파일이 빠짐없이 들어 있는지 검사합니다. 설치·복귀 왕복 검증도 실제로 설치된 Herdr 파일을 해시로 확인합니다.
- **업데이트하면 자동 복구**: v2.0.0에서 Herdr가 멈춘 채 남아 있던 호스트를 다음 실행 때 교체합니다. Herdr 서버가 응답하지 않고, 기록된 Herdr·터미널 프로세스가 모두 종료됐고, 호스트 프로세스 신원이 일치할 때만 교체합니다. 실행 중일 수 있는 작업이 있으면 호스트를 건드리지 않습니다.
- **원인 표시**: 앱을 시작할 때 Herdr 구성 파일을 확인합니다. 백신 격리 등으로 파일이 빠지거나 바뀌었으면, 해당 파일 이름과 재설치 방법을 시작 오류 창에 표시합니다. 실행 중 Herdr 서버가 멈추면 `Operation rejected` 대신 앱을 다시 열라는 안내와 로그 위치(`herdr/herdr-server.log`)를 보여 줍니다.

Android 기능·실기기 검증은 v2.0.0과 같이 사용자 요청에 따라 제외했습니다. 이번 수정은 Windows 설치본·호스트에만 해당하며 Android 셸은 바뀌지 않았습니다. 검증 근거와 대상 커밋은 [출시 검증 기록](v2-validation.json)에 있습니다.
