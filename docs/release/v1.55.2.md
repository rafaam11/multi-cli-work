# v1.55.2 — 에이전트가 띄운 앱에서도 세션을 새로 시작

v2.0.x(Herdr) 라인을 폐기하고 v1.55.1로 돌아온 뒤의 첫 패치입니다. v2.0.0·v2.0.1 릴리스는 내려갔고, 이 버전은 v1.55.1에서 이어집니다.

- **상속된 에이전트 세션 변수 제거**: Claude Code 같은 에이전트가 자기 도구 셸에서 앱을 실행하면(`Start-Process` 등), 앱 안의 모든 터미널이 그 에이전트의 세션 표식을 물려받았습니다. 그래서 앱 안의 Claude Code가 자신을 중첩 세션으로 여겨 대화 기록 저장을 끄고("Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker"), 함께 넘어온 `NO_COLOR` 때문에 흑백으로 표시됐습니다. 이제 세션을 열 때 `CLAUDECODE`·`CLAUDE_CODE_CHILD_SESSION`·`CLAUDE_CODE_SESSION_ID`·`CLAUDE_PID`·`AI_AGENT`와 Codex 샌드박스 표식 같은 세션 표식을 항상 뺍니다.
- **도구 셸 설정은 표식이 있을 때만 제거**: 같은 도구 셸이 넣는 `NO_COLOR`·`GIT_EDITOR=true`·`GIT_TERMINAL_PROMPT=0`·`PSExecutionPolicyPreference=Bypass` 등은 위 표식과 함께 들어왔을 때만 뺍니다. 직접 설정한 `NO_COLOR`나 git 설정은 그대로 유지합니다. Windows에서는 변수 이름을 대소문자 구분 없이 비교합니다.

**한계**: 이미 열려 있는 앱 프로세스에는 적용되지 않습니다. 업데이트 후 앱이 다시 시작될 때부터 새로 여는 세션에 적용됩니다. `~/.claude/settings.json`의 `env`처럼 사용자 설정에서 오는 값(`CLAUDE_CODE_SUBAGENT_MODEL` 등)은 건드리지 않습니다.

**검증**: Windows에서 Vitest 243개 파일·2,377개 테스트, 타입 검사, 프로덕션 빌드를 통과했습니다. 새 단위 테스트는 실제로 이 문제를 일으킨 환경 변수 목록으로 Windows·Linux를 모두 확인합니다. 패키징된 앱에서 직접 확인하지는 않았습니다. 릴리스 CI에서 Windows·Linux 전체 테스트와 E2E·패키징을 다시 수행합니다.
