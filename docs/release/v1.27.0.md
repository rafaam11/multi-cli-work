# v1.27.0 — 사이드바 3단 트리와 세션 패널

ws-root 워크스페이스를 등록하면 사이드바가 `채널 › 셸 › 레포 › (worktree ›) 세션`으로 4~5단까지 깊어졌다.
이제 트리는 **채널 › 프로젝트 › 폴더** 딱 3단이고 폴더가 잎이다. 세션·문서 행은 트리에서 나와 사이드바
하단의 **세션 패널**에 평면으로 선다 — 트리는 "어디에 뭐가 있나"를, 패널은 "지금 무엇이 나를 기다리나"를
답한다. worktree 관리는 폴더 상세 페이지의 **워크트리 카드**로 옮겼다.

세션 행을 트리에서 뺐다가 되돌린 적이 한 번 있다. 되돌린 이유는 "다른 폴더가 뭘 들고 있는지"가
안 보여서였는데, 이번에는 패널의 기본 범위가 **전체**라 그 가시성이 그대로 남는다.

## 변경 사항

- **폴더는 잎이다.** 체버론이 없고, 누르면 그 폴더의 그리드가 열린다. 이미 열린 폴더를 다시 눌러도 접히지
  않는다(접을 것이 없다) — "다시 누르면 접힌다"는 프로젝트 행에만 남는다. 드래그 정렬·그룹 이동, 우클릭
  메뉴, 브랜드 아이콘, 폴더 없음 표시, 읽지 않음 배지, 세션 수(worktree 것 포함)는 그대로다
- **세션 패널.** 모든 세션과 문서 패인, 폴더 없는 도구 세션(`Claude Code 업데이트` 등)까지 한 목록에 선다.
  순서는 **승인 대기 → 입력 대기 → 작업 중·시작 중 → 나머지**, 같은 등급 안에서는 최근 갱신순. 화면 밖에서
  시작된 대기(읽지 않음)는 상태가 이미 지나갔어도 그 등급으로 올라온다. 문서는 언제나 세션 뒤. 각 행에
  `폴더명 ⎇ 브랜치 · 이름` 소속이 붙고, 클릭·우클릭 메뉴·이름 바꾸기·작업공간/그리드 슬롯으로 드래그는
  트리에 있을 때와 같다. 옛 "도구" 그룹은 없어졌다
- **`전체 | 여기` 범위.** 기본은 전체. "여기"는 지금 보는 폴더(그 폴더의 worktree 세션 포함)·worktree·업무
  프로젝트의 세션만 남긴다. 홈·작업공간·숨김처럼 범위로 삼을 폴더가 없는 화면에서는 버튼이 꺼지고 전체가
  보이되 저장된 선호는 지우지 않는다. 헤더의 **`대기 N`** 배지는 패널을 접어도 남는다
- **워크트리 카드** — 폴더 상세 페이지의 "Git 상태" 아래. 브랜치·변경 수·세션 수·PR 리뷰·locked/missing/prunable
  표시, **열기**, 행 **우클릭**으로 지금까지의 worktree 메뉴(새 세션·탐색기·에디터·변경 보기·fetch·unlock·정리·
  제거·PR) 그대로, 헤더의 **워크트리 만들기**(폴더가 사라진 상태에서는 꺼진다). worktree에 스코프된 페이지에서도
  보이므로 형제 worktree로 바로 옮겨 갈 수 있다. worktree 경고도 이 카드에 뜬다
- **트리 컨트롤 모두 / 접기 / 작업중**이 채널까지 다룬다. "작업중"은 돌아가는 폴더를 가진 프로젝트와 그 채널만
  펼치고 나머지는 접는다
- 업무 프로젝트 페이지에서 "여기"의 이름은 셸 폴더명(`O_SMCH/24_SMCH_VSP-1`)이 아니라 셸의 한글 `title`이다 —
  사이드바가 부르는 이름과 같다

## 호환성

- 렌더러만 바뀌었다. `projects.json`·`state.json`·`work-projects.json`·`workspace.json`·`worktrees.json` 스키마와
  main 프로세스·IPC는 무변경
- 사이드바 접힘 상태(`multi-cli-work.sidebar.v1`)에 `sessionPanelOpen`·`sessionScope` 키가 **추가**된다. 버전은
  그대로라 구버전 앱은 모르는 키를 무시하고, 폴더 접힘을 저장하던 옛 키(`multi-cli-work.projects.v1`)는 읽지도
  지우지도 않으므로 다운그레이드하면 그 배치가 그대로 살아 있다
- 세션·문서 행의 접근성 이름(`… 세션 열기`, `… 문서 열기`, `… 닫기`)은 바뀌지 않았다. 소속(폴더명·브랜치)은
  눈에 보이는 글자와 툴팁에만 있고 스크린 리더 이름에는 들어가지 않는다 — 알고 받아들인 트레이드오프이며 별도
  작업으로 남긴다
- 폴더 그리드 안에서 worktree 세션의 패인에 초점을 주면 앱이 그 worktree로 다시 스코프되는 것은 이전과 같은
  동작이다. 새 패널의 "여기"도 그만큼 좁아진다
- 손으로 만든 업무 프로젝트와 미분류 폴더는 이전처럼 채널 없이 최상위에 선다
