# v1.19.0 — 패인 헤더가 자기 자리를 말한다

한 페이지에 패인이 12칸까지 들어가면서, 화면에 뜬 터미널이 **어느 폴더의 것인지**가 눈으로
구분되지 않았다. 헤더가 말해주는 것은 세션 이름뿐인데 그 이름은 사용자가 붙이지 않으면
프로바이더가 준 제목이거나 "Claude 2" 같은 번호여서, 소속을 담고 있지 않다. 이제 헤더가
두 줄이 되고 윗줄이 그 패인의 자리를 적는다.

## 변경 사항

- **패인 헤더가 두 줄이 된다.** 윗줄은 이 패인이 어디에 있는지를 — **폴더 → 브랜치 → 업무
  프로젝트** 순서로 — 적고, 아랫줄은 지금까지처럼 상태 점·에이전트 아이콘·세션 이름·버튼을
  담는다. 각 조각은 아이콘(폴더/브랜치/서류가방)을 앞에 달고, 구분자로 가운뎃점을 쓰지 않는다.
  조각이 사라졌을 때 구분자만 남는 일이 없게 하기 위해서다
- **좁아지면 오른쪽부터 접힌다.** 열을 좁히면 업무 프로젝트 이름이 먼저 줄어 사라지고, 그다음
  브랜치, **폴더 이름이 마지막까지 남는다** — 두 패인을 갈라주는 것이 폴더 이름이기 때문이다.
  잘린 문구는 전부 헤더의 툴팁에 들어 있다
- **업무 프로젝트 색이 헤더를 탄다.** 사이드바가 쓰는 카테고리 색(정부지원과제·외주개발·
  상품개발·기타)이 헤더 왼쪽 2px 띠로 그려져, 글자를 읽기 전에 소속이 갈린다. 업무 프로젝트에
  묶이지 않은 폴더도 띠 자리(투명)를 그대로 지켜서 한 화면의 모든 헤더가 같은 x에서 시작한다
- **워크트리 세션은 브랜치로 갈린다.** 같은 레포의 메인 세션과 워크트리 세션을 나란히 놓아도
  브랜치 이름이 둘을 구분한다. 워크트리가 이미 제거된 세션은 있지도 않은 브랜치를 말하는 대신
  폴더 이름만 적는다
- **폴더 밖 세션은 "도구"라고 적는다.** CLI 업데이트 같은 유지보수 세션은 폴더가 없으므로
  퀵오픈이 쓰는 것과 같은 단어를 렌치 아이콘과 함께 단다. 등록이 끊긴 폴더는 세션의 실제 작업
  디렉터리 마지막 조각으로 이름을 대신한다
- **문서 패인도 같은 줄을 받는다.** 파일·diff·커밋 그래프·PR 패인은 자기가 열린 폴더/워크트리를
  같은 방식으로 적고, 헤더 오른쪽에서 같은 말을 반복하던 라벨은 사라진다

## 검증

- Vitest 전체 통과 (86파일 889테스트) — 폴더·브랜치·업무 프로젝트를 세션과 문서에서 각각
  풀어내는 순수 모듈(미분류 폴더, 등록이 끊긴 폴더, 사라진 워크트리, 폴더 밖 세션 포함)과
  헤더가 그 결과를 그리는 방식·카테고리 클래스가 붙는 위치를 새 테스트로 덮었다
- TypeScript typecheck 및 프로덕션 빌드 통과
- Electron E2E 전체 통과 (17/17, 로컬 Windows) — 실제 앱에서 두 패인이 모두 자기 폴더 이름을
  헤더에 띄우는지, 두 줄이 된 뒤에도 헤더 드래그·우클릭 메뉴·제목 더블클릭 이름 변경이
  그대로인지 확인했다
