# v1.26.0 — ws-root 워크스페이스 루트: 채널 › 셸 › 레포 트리와 셸 브리프

`C:\work`(채널·프로젝트 셸) · `C:\dev`(개발 레포) · `C:\data`(데이터셋) 3형제 루트를 등록하면,
사이드바가 **채널 › 셸 › 레포 › 세션** 트리로 바뀌고 Claude Code 세션 브리프에 "이 폴더가 어느 셸의 일인지"가 실린다.
루트 원칙(`<work>\CLAUDE.md`)은 셸 안에서는 상위 캐스케이드로, 레포 안에서는 `CLAUDE.local.md` 임포트로 이미 읽히므로,
앱은 **동적 정보**(형제 레포 절대경로·데이터셋 경로·형제 셸)만 얹는다.

## 변경 사항

- **워크스페이스 루트 등록.** 설정 › `워크스페이스 루트`에서 `work` 폴더를 고르면 `dev`·`data`는 드라이브 직하위 형제
  폴더로 찾아 함께 기록한다(`DEV_ROOT`/`DATA_ROOT`로 다른 위치를 쓰는 PC도 지원). 등록 목록은
  `~/.multi-cli-work/workspace.json`에 **따로** 산다 — `projects.json`·`state.json`·`work-projects.json` 스키마 무변경
  (레지스트리 계약 §8, 다운그레이드 안전)
- **경로 유도.** 열린 폴더가 `<work>\<채널>\<셸>`이면 셸, `<dev>\<레포>`이면 레포로 분류하고, 셸 `CLAUDE.md` 프론트매터
  `repos:`·`external_paths:`를 역인덱스로 읽어 **루트 밖 레포(예 `C:\NeuroPilot\…`)도 자기 셸을 안다**. 규칙은 ws-root의
  `_scripts/lib/ws-path.mjs`와 같은 정규식(채널 `^[GORZP]_…`, 셸 `YY_<채널>_<Topic>-<n>`)
- **사이드바 트리.** 채널(G 과제·O 용역·R 연구·Z 기타·P 개인, 글자별 색) › 셸(`title:` 한글 표시명) › 레포·셸 폴더 › 세션.
  기존 "업무 프로젝트" 수동 멤버십이 있으면 그것이 우선하고, 루트를 등록하지 않으면 **이전과 완전히 같은 트리**다
- **업무 프로젝트 자동 보강.** 셸마다 업무 프로젝트를 upsert하고(`category`는 채널 글자로), 어느 항목이 자동 생성인지는
  `workspace.json`의 `shellLinks`에 둔다 — 사용자가 손으로 만든 항목·메모는 덮어쓰지 않는다
- **세션 브리프 확장.** Claude Code 세션의 SessionStart 훅에 `# 워크스페이스: <채널>/<셸>` 절이 추가된다: 셸 title·status,
  루트 원칙 경로, 셸 `wiki/data.md` 앞부분, 같은 셸의 형제 레포 절대경로, 같은 채널의 형제 셸, 셸이 쓰는 데이터셋
  경로(`<data>/index.md`). 기존 업무 프로젝트 브리프가 있으면 한 파일로 합쳐진다. 워크스페이스에는 아무것도 쓰지 않는다
- 앱 시작과 `workspace:sync` 때 루트를 다시 훑어 폴더가 옮겨진 뒤에도 스스로 고친다

## 호환성

- 루트 미등록 시 동작·저장 파일 전부 이전과 동일. `projects.json` 스키마·파서 무변경
- `workspace.json`은 잠금·원자적 쓰기·`.bak` 프로토콜(계약 §4~§6)을 그대로 따른다
- Codex 세션에는 브리프를 주입하지 않는다(이전과 같음)
