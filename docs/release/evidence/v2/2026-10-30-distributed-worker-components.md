# Distributed worker implementation evidence

This is component/integration evidence, not a completed physical multi-PC release check.

The owner host retains the only canonical task. Each foreign worker host stores a separate `worker-replicas-v2.json` with its own execution observation and a durable operation outbox. The owner's `remote-workers-v2.json` binds the selected worker attempt to its confirmed registered checkout. The runtime polls over the existing authenticated SSH host client; closing the GUI does not own that loop.

Before any provider command, every selected checkout/worktree is prepared. The worker host resolves its own saved profile and executable and rechecks its path and full base commit at admission. The owner persists a unique admission intent first. An uncertain reply is never retried. A later read of the same worker attempt can settle that command's delivery; it cannot launch it. Idle is not completion. Lost observations retain the original timestamp.

Messages, questions, approval requests and results have stable operation IDs and authenticated task/participant/attempt/generation identity. The owner atomically commits data and deduplication receipts. The worker only acknowledges an operation when the returned canonical task proves it was committed. An interrupted acknowledgement leaves the local operation available for the next sync, without duplicating the owner's event or result. Results remain unintegrated and pending user review.

Windows component tests cover lost admission replies across restart, unavailable links, duplicate receipts, stale/forged identities, changed checkout/profile selection, separate worktrees and no later admission after an uncertain command. A two-gateway HTTP integration test creates real Git fixture repositories and owned worktrees, uses the full catalog/start/replica/MCP path, wakes a waiting lead with a remote question, exchanges a targeted worker message, recovers an offline result exactly once and checks both original checkouts remain clean. Its terminal broker is a fixture: it does not start real Claude/Codex processes or prove SSH/device behavior.

Task MCP clients now reread their private connection file before each new request. A restarted host refreshes only a matching persisted capability file to its new endpoint. A failed request is not replayed; its response warns that a mutation may already have committed. Tests demonstrate a new request using the new port and preservation of request counts.

Remaining checks include desktop placement controls, actual distributed Claude/Codex behavior over SSH, multi-PC failure recovery, terminal interactions/performance, production recovery roundtrips and mobile implementation. Android verification is deferred by explicit user authorization; none of these tests claims Android validation. Stable/latest is unchanged.

The Windows source GUI survival/reconnect test passed in 18.7 seconds. Typecheck and the v2 build passed; the full suite passed 285 files / 2579 tests (2 files / 4 tests environment-skipped), with the real provider hook file separately passing 10 tests. A new local three-provider probe did **not** pass: the Claude worker displayed `Login expired`, while the saved account credential was expired. The run preserved diagnostics and cleaned up its own processes and copied credentials. The probe now requires a login valid beyond its bounded runtime, preventing fixture copies from attempting to refresh an expired shared account credential. Existing earlier successful provider evidence remains historical; it is not a passing result for this checkpoint.
