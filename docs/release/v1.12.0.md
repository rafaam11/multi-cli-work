# v1.12.0 — VS Code 스타일 커스텀 타이틀바

## 변경 사항

- OS 타이틀바 + Electron 기본 영어 메뉴(File/Edit/View/Window/Help) 두 줄(약 60px)을 35px 한 줄 커스텀 타이틀바로 대체
- 한국어 메뉴 6개 — 파일 / 편집 / 보기 / 세션 / 도구 / 도움말. 폴더가 없으면 세션 메뉴가, 터미널이 아니면 편집 메뉴가 비활성
- 커맨드센터에 현재 업무 프로젝트 / 폴더 표시, 클릭 시 빠른 열기(`Ctrl+P`). 옆에 대기 표시 — `!`(승인 대기) / `●`(입력 대기)
- 최소화 / 최대화·복원 / 닫기 버튼을 직접 렌더링. 닫기는 기존대로 트레이로 숨김, 종료는 파일▸종료
- 편집 메뉴(복사·붙여넣기·모두 선택·터미널 지우기)는 **마지막으로 포커스를 받은 xterm**을 대상으로 동작 — 화면 분할 상태에서 좌우 pane을 구분
- 네이티브 메뉴가 갖고 있던 액셀러레이터 이전: `F11`(전체 화면) · `F12`(개발자 도구) · `Ctrl+=` / `Ctrl+-` / `Ctrl+0`(확대·축소·원래 크기). `Ctrl+R` 다시 로드는 오타 위험 때문에 메뉴 항목으로만 제공
- 키보드 조작: Esc 닫기, ↑/↓ 항목 이동, ←/→ 최상위 메뉴 전환, Enter 실행, 열린 상태에서 hover 전환

## 검증

- 신규 단위 테스트 — 창 크롬 옵션(win32 `titleBarStyle: "hidden"` / linux `frame: false`), 메뉴 활성화 규칙, 타이틀바 상호작용, `window:*` IPC 위임 (Vitest 71개 파일, 605개 테스트 통과)
- TypeScript typecheck 및 프로덕션 빌드 통과
- Electron E2E 15개 시나리오 통과 (타이틀바가 상단 0px에 35px로 붙어 있고 네이티브 메뉴가 제거되었는지 포함)

## 알려진 한계

- Windows 11 스냅 레이아웃 호버 팝업은 창 버튼을 직접 그리면서 사용할 수 없다 (Win+화살표 스냅은 그대로 동작)
- Linux는 `frame: false`라 창 가장자리 리사이즈 히트 영역이 얇다
