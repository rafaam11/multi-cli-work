# v1.49.0 — 세션 협업: 안전한 jk send, 팀 보드, 팀 프리셋, jk MCP 도구

여러 세션이 서로 일을 넘기고 결과를 나누도록, 세션 사이에 글을 보내는 길과 함께 보는 자리를 새로 만들었다.

- **jk send 보류**: `jk send`는 이제 대상의 프롬프트에 바로 쓰지 않는다. 대상이 작업 중이거나 승인을 기다리거나, 사람이 입력 중이거나, 첫 실행 확인 창(Claude 폴더 신뢰·권한 우회 경고, Codex 훅 신뢰·폴더 승인)이 떠 있으면 보류했다가 한가해지면 한 건씩 넣는다. 본문과 Enter는 떼어 보내서, 긴 한 줄을 Claude가 붙여넣기로 받아 제출하지 않던 일이 없다. 보류 개수는 대상 패인 머리줄의 `보류 N` 칩으로 보이고, 받는 쪽에는 `[from <이름> (<kind>)]`가 앞에 붙는다. `jk send --now/--raw/--wait`, `jk broadcast`, `jk held [--drop]`, `jk spawn --name --prompt`를 더했다.
- **팀 보드**: 오른쪽 사이드바 `보드` 탭에 폴더마다 피드가 하나씩 있다. 사용자와 세션(`jk post`)이 글을 올리고, `@`로 멘션한 세션에는 프롬프트로도 들어간다. 세션끼리 주고받은 send는 보낸 쪽과 받는 쪽을 잇는 선으로 보이며, 보류·전달·실패가 선 모양으로 구분된다. `jk board`로 읽는다.
- **팀 프리셋**: 폴더·워크트리 우클릭 메뉴, 폴더 시작 화면의 "팀으로 시작", 빈 보드에서 여러 세션을 한 번에 띄우고 각자 역할 프롬프트를 넣는다. 기본 예시는 "빌더 + 리뷰어"(Claude 빌더, Codex 리뷰어)이고, 설정 › 팀 프리셋에서 고친다.
- **jk MCP 도구**: Claude·Codex 세션에 jk 명령(`jk_list`·`jk_send`·`jk_wait`·`jk_spawn`·`board_post` 등 11개)을 MCP 도구로 붙인다. 앱이 세션마다 설정을 넘기므로 Claude·Codex 전역 설정은 바뀌지 않는다. 설정 › 일반의 "Claude·Codex 세션에 jk 도구(MCP) 제공"(기본 켬)으로 끄며, 새로 시작하는 세션부터 적용된다.

실제 Claude Code에서 빌더 세션이 `jk_list`·`jk_send`·`board_post` MCP 도구로 다른 세션과 보드에 글을 넘기는 것을 두 번 연속 확인했다. 전체 단위 테스트 2,170개, 타입 검사, Windows·Linux Electron E2E를 통과했다.

알려진 문제: Codex 세션이 훅 신뢰 확인 창에 답한 뒤에도 그 세션으로 가는 글이 보류로 남는 경우가 있다. 이때는 `jk held --drop`으로 취소하거나 직접 입력한다.

보류 중인 메시지는 메모리에만 있어 앱을 재시작하면 사라진다. 팀 보드는 `userData/board/`, 팀 프리셋은 `~/.multi-cli-work/session-presets.json`에 저장한다. 폰 앱은 바뀌지 않았다.
