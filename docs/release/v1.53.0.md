# v1.53.0 — 업무 프로젝트 레포를 한 번에 최신화한다

다른 PC에서 push하고 돌아오면 업무 프로젝트의 레포를 하나씩 열어 pull해야 했다. 이제 업무 프로젝트 화면에서 한 번에 받거나, 세션을 시작할 때 자동으로 받는다.

- **대상**: 업무 프로젝트의 레포 멤버 폴더, 연결된 셸의 `repos:`(`<dev>/<레포>`)와 `external_paths:`를 합친다. `_archive`로 옮긴 휴면 레포와 클라우드 동기화 폴더(구글 드라이브, OneDrive, Teams) 아래 경로는 뺀다.
- **동작**: `fetch --prune` 뒤 fast-forward만 한다. merge, rebase, stash, reset은 하지 않는다. 추적 파일에 커밋 안 한 변경이 있거나 원격과 갈라진 레포는 건너뛰고 사유를 남긴다. 추적 안 된 파일만 있는 레포는 진행한다.
- **"모든 레포 최신화" 버튼**: 업무 프로젝트 화면의 "레포 최신화" 카드에 있다. 레포마다 최신화됨(N커밋) / 이미 최신 / 건너뜀(사유) / 실패(오류)로 보여 주고, 화면을 열면 마지막 기록부터 보인다.
- **세션 시작 때 자동**: 업무 프로젝트 폴더에서 Claude Code나 Codex 세션을 열면 그 프로젝트의 레포를 최신화한다. 최대 3초까지 기다려 그때까지의 요약을 세션 첫 컨텍스트에 넣고, 남은 레포는 뒤에서 마저 받는다. 네트워크·인증 실패가 세션 시작을 막지 않는다. 같은 레포는 동시에 두 번 돌지 않고, 최신화된 레포는 10분 동안 다시 받지 않는다. 설정 > 일반에서 끌 수 있다.
- **건너뜀·실패 알림**: 세션 시작 때 건너뛰거나 실패한 레포가 있으면 알림이 뜬다. 누르면 그 업무 프로젝트 화면으로 간다.
- **Codex 브리프**: Codex 세션도 Claude처럼 업무 프로젝트 브리프를 세션 시작 컨텍스트로 받는다.

**고친 것**: Claude 세션에 들어가던 업무 프로젝트 브리프의 한글이 깨져 있었다(Windows PowerShell 5.1의 출력 인코딩). 이제 그대로 들어간다.

**harness-manager와의 관계**: 최신화 엔진과 정책은 harness-manager가 정한다(`docs/contracts/repo-sync.md`). 설치된 harness-manager가 있으면 그 CLI를 부르고, 없으면 같은 정책을 따르는 내장 엔진으로 돈다. 두 쪽은 `~/.harness-manager/repo-sync/`의 기록과 잠금을 함께 쓴다.

**Codex hook**: hook 정의는 그대로이고 스크립트 내용만 바뀌었다. 업데이트 뒤 Codex가 hook을 다시 신뢰하라고 하면 `/hooks`에서 승인한다.

**검증**: 타입 검사와 단위 테스트를 통과했다. 실제 git 픽스처로 fast-forward, 로컬 변경, 갈라짐, upstream 없음, 원격 실패, 동시 호출 중복 제거를 확인했다. 개발 빌드에서 버튼, 세션 시작 브리프, 건너뜀 알림을 확인했고, `codex exec`로 Codex 브리프 주입을 확인했다.
