# v1.26.1 — 폴더 우클릭 메뉴에서 바로 폴더 다시 연결

폴더를 다른 자리로 옮긴 뒤 앱에 새 경로를 알려주는 **폴더 다시 연결**은 지금까지 타이틀바 `파일`
메뉴, 그리드 헤더 버튼, 폴더가 사라졌을 때 뜨는 배너 세 곳에만 있었다. 셋 다 **지금 선택한 폴더**
하나를 가리키므로, 옮긴 폴더가 선택된 폴더가 아니면 먼저 그 폴더를 선택해야 했다 — 그런데 사라진
폴더를 선택하면 그리드는 아무것도 시작할 수 없는 화면으로 바뀐다. 이제 사이드바 우클릭 메뉴에 같은
항목이 있어, 트리에서 그 폴더를 가리킨 채 곧바로 새 경로를 지정한다. GitHub Desktop이 옮겨진 저장소에
`Locate…`를 주는 것과 같은 자리다.

## 변경 사항

- **폴더 우클릭 메뉴에 `폴더 다시 연결`이 생겼다.** 메뉴는 **새 세션 → 파일 탐색기/VS Code/GitHub에서
  열기 → Worktree 만들기 → 이름 변경 → 폴더 다시 연결 → 목록에서 제거** 순이 된다. 항목이 메뉴를 연
  폴더에 직접 작용하므로 **선택하지 않은 폴더도**, 그리고 **사라지지 않은 폴더도** 그 자리에서 경로를
  바꾼다 — 폴더를 옮기는 일은 폴더가 사라져 보이기 전에도 일어나기 때문이다
- **선택 대화상자가 옛 경로의 상위 폴더에서 열린다.** 옮긴 폴더는 대개 원래 자리의 형제라, OS 기본
  위치가 아니라 옛 루트 옆에서 찾기 시작한다. 옛 상위 폴더까지 사라졌다면 Electron이 기본 위치로
  떨어지므로 그때도 막히지 않는다. 파일 메뉴·헤더 버튼·배너에서 여는 대화상자에도 함께 적용된다
- **다시 연결한 뒤에도 그 폴더의 것은 그대로다.** 세션·메모·업무 프로젝트 소속과 폴더 id가 유지되고,
  워크스페이스 루트를 쓰는 경우 새 경로 기준으로 셸 소속이 다시 계산된다. 이미 등록된 다른 폴더의
  경로를 고르면 예전처럼 거부한다
- 내부적으로 `relinkProject`가 대상 폴더를 인자로 받도록 일반화됐고, 기존 세 진입점은 선택된 폴더를
  넘기는 한 갈래(`relinkSelectedProject`)로 합쳐졌다

## 호환성

- 저장 스키마·IPC 계약 무변경. `projects:relink`는 예전처럼 프로젝트 id 하나만 받는다
- 기존 진입점 세 곳(파일 메뉴 · 헤더 버튼 · 누락 배너)의 라벨과 동작은 그대로다
- 우클릭 메뉴는 예전처럼 읽기 전용 레지스트리 여부를 따로 따지지 않는다(`이름 변경`·`목록에서 제거`와
  같다) — 쓰기가 막혀 있으면 기존 오류 배너가 사유를 띄운다

## 검증

- Vitest 전체 통과 (103파일 1117테스트, 이전 1114에서 3개 추가) — 새 테스트는 ① 선택하지 않은 누락
  폴더를 우클릭 메뉴에서 다시 연결하면 그 행의 `📁✕`가 풀리고 경로가 갱신되는지, ② 대화상자를 취소하면
  아무것도 바뀌지 않고 오류도 뜨지 않는지, ③ IPC가 옛 루트의 상위 폴더를 기본 경로로 넘기고 취소 시
  레지스트리에 손대지 않는지를 덮는다. 기존 relink 테스트(헤더 버튼 경로)와 폴더 우클릭 메뉴 테스트는
  그대로 통과한다
- TypeScript typecheck 및 프로덕션 빌드 통과
- Electron E2E smoke 통과 (9/9, 로컬 Windows) — 폴더 우클릭 메뉴를 실제로 여는 기존 경로가 항목이 하나
  늘어난 메뉴에서도 그대로 동작한다
- 릴리스 CI가 Windows 2022와 Ubuntu 22.04 x64에서 전체 Electron E2E와 패키징을 재검증한다
