# v1.40.0 — 워크트리 스크립트, diff 줄 메모, jk 상태 칩

Orca와 cmux에서 가져온 에이전트 작업 흐름 세 가지다. worktree를 만들면 바로 쓸 수 있게 준비되고, 변경을 보다가 그 자리에서 에이전트에게 고칠 것을 넘긴다. 스크립트와 에이전트는 자기 상태를 그리드에 직접 내건다.

## 바뀐 것

- **워크트리 준비·정리 스크립트**
  - 폴더 상세 페이지의 **워크트리 스크립트** 카드에 폴더별로 적어 둔다.
  - 새 worktree를 만들면 **준비 스크립트**가 그 worktree의 셸 세션 `셋업 · <브랜치>`에서 돈다. 예: `npm ci`, `.env` 복사. 진행 과정이 보이고, 세션은 바로 화면에 뜬다.
  - worktree를 제거하면 세션을 멈춘 뒤 **정리 스크립트**가 숨어서 먼저 돈다. 제한 시간은 기본 120초이고 1~3600초로 정할 수 있다.
  - 정리 스크립트가 실패하거나 시간을 넘기면 worktree는 그대로 두고 출력 끝부분을 보여 준다. **스크립트 없이 제거**는 따로 눌러야 한다.
  - 두 스크립트 모두 `MCW_ROOT_PATH`, `MCW_WORKTREE_PATH`, `MCW_BRANCH` 환경 변수를 받는다.
  - Windows는 지금 셸(pwsh 또는 Windows PowerShell)로, Linux는 bash로 실행한다.
  - 스크립트는 `~/.multi-cli-work/worktree-scripts.json`에만 있고 레포에는 아무것도 쓰지 않는다. 폴더를 목록에서 지우면 그 폴더의 스크립트도 지워진다.
  - PR 리뷰용 worktree는 이 흐름을 타지 않는다. 리뷰 완료 흐름에서 정리된다.
- **diff 줄 메모**
  - Git 탭에서 연 변경 비교 화면(HEAD ↔ 작업 트리)에서 줄 번호를 누르면 그 줄에 메모를 남긴다. 메모가 있는 줄에는 여백에 점이 찍힌다.
  - 그 체크아웃의 모든 파일 메모가 비교 화면 아래에 모인다. **메모 N개 보내기**로 같은 폴더(또는 같은 worktree)에서 돌고 있는 세션 하나에 한 번에 보낸다.
  - 기본 대상은 마지막으로 입력한 세션이다. 보내고 나면 그 세션으로 간다.
  - 형식은 PR line note와 같다(경로·쪽·줄·코드·요청). 여러 줄은 bracketed paste로 한 번에 들어간다.
  - 메모는 이 PC의 브라우저 저장소에만 있다. 보낸 메모는 1주일 뒤, 사라진 폴더·worktree의 메모는 바로 정리된다.
- **`jk status` / `jk progress`**
  - `jk status set <key> <텍스트…> [--color green|amber|red|blue|gray]`는 지금 세션의 패인 머리줄과 홈 대시보드 행에 칩을 붙인다. `jk status clear [key]`로 뗀다.
  - 칩은 세션마다 8개, 40자까지다. 제어 문자는 걸러낸다. 바뀔 때 짧게 반짝인다.
  - `jk progress <0-100|busy|clear> [--state normal|error|warning]`은 머리줄 밑 진행선과 작업표시줄을 움직인다. 홈 대시보드 행에는 `· 40%`로 보인다.
  - `jk progress`로 건 진행률은 명령이 끝나도 남는다. 세션 출력이 알린 진행률은 그 일이 끝나면 지워지는 것과 다르다.
  - 다른 세션을 대상으로 하려면 `--session <id>`를 붙인다.

## 고친 것

- **앱 안의 터미널에서 띄운 다른 인스턴스의 `jk`가 거절됐다**
  - 예를 들어 이 앱 안에서 `npm run dev`로 개발판을 띄운 경우다. 개발판은 부모 세션의 `JK_CODING_CLI_PIPE`를 물려받아 부모의 파이프 이름을 썼다.
  - 그래서 개발판 세션의 `jk`가 부모 앱으로 가서 "이 앱 인스턴스가 발급한 토큰이 아닙니다"로 거절됐다.
  - 이제 세션 토큰과 함께 물려받은 파이프 이름은 무시하고 자기 파이프를 쓴다.

## 검증

- 단위 테스트 전체 1,944개를 통과했다. 새로 붙인 것:
  - 스크립트 저장소(검증·상한)와 실행기(BOM, 환경 변수 따옴표, 타임아웃, 출력 끝 4KB, 시작 실패)
  - 제거 순서(세션 중지 → 정리 → git), 정리 실패와 건너뛰기
  - 줄 메모 형식(PR 프롬프트 바이트 동일), 메모 저장·정리, 전송 대상 거르기, 비교 화면 메모 편집·전송
  - `jk status`·`progress` 검증과 상한, 상속된 파이프 이름 판정
- TypeScript 검사와 프로덕션 빌드를 통과했다. 내장 `jk` 클라이언트(PowerShell·Python)는 문법 검사를 통과했다.
- Electron E2E `desktop.spec.ts` 26개를 통과했다. 실제 앱에서 확인한 장면:
  - 준비 스크립트가 `셋업 · feature/scripts` 세션에서 `MCW_BRANCH`를 출력한다
  - 정리 스크립트가 코드 3으로 끝나면 출력과 함께 제거가 멈추고, "스크립트 없이 제거"로 지워진다
  - 비교 화면의 1번 줄에 남긴 메모가 같은 폴더의 셸로 간다
  - 셸에서 `jk status set`·`jk progress`로 칩과 30% 진행선이 생기고, `clear`로 사라진다
