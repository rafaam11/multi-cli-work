# v1.49.1 — Codex 훅 확인 창 뒤 jk 전달 보류 수정

Codex 세션이 훅 신뢰 확인 창에 답한 뒤에도 그 세션으로 가는 글이 보류로 남던 문제(v1.49.0의 알려진 문제)를 고쳤다.

- **원인**: 확인 창에 답하는 Enter를 앱이 프롬프트 제출로 보고 세션을 작업 중으로 표시했다. 실제로는 턴이 시작되지 않으므로 Codex가 끝났다는 신호를 보내지 않았고, `jk send`·보드 멘션·팀 프리셋의 역할 프롬프트가 30분 만료까지 `작업 중` 사유로 보류됐다.
- **수정**: 확인 창에 답한 키로 생긴 작업 중 상태에서는 전달을 보류하지 않는다. 세션이 다음 상태를 알리거나 사람이 다시 입력하면 원래 규칙으로 돌아간다. 전달 큐가 보낸 Enter는 실제 턴을 시작하므로, 그 뒤에는 다시 턴이 끝나기를 기다린다.
- 확인 창 감지도 다듬었다. Codex는 답한 뒤 훅 창을 한 번 더 그리는데, 이 그림 때문에 보류가 다시 걸리지 않도록 창 문구 뒤에 입력창(`Ask Codex to do anything`·`? for shortcuts`)이 그려지면 창이 닫힌 것으로 본다.

실제 Claude Code·Codex로 확인했다. 보드 멘션을 받은 Claude 빌더가 `jk_list`·`jk_send`·`board_post` MCP 도구로 Codex 리뷰어에게 글을 넘겼다. 리뷰어는 훅 확인 창에 답한 뒤 그 글을 받아 `board_post`로 보드에 수신 확인을 올렸다. 전체 단위 테스트 2,171개와 타입 검사를 통과했다.

저장 형식과 폰 앱은 바뀌지 않았다.
