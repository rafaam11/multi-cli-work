# v1.16.0 — 세션·문서 목록의 사이드바 복귀 + 세션 제거 확인 팝업 제거 + 새 패인 자동 작업공간 배치

## 변경 사항

- **열려 있는 세션과 문서가 다시 왼쪽 트리에 선다.** v1.13에서 그리드 위 한 줄(패인 탭 바)로 옮겼던 목록을 사이드바로 되돌렸다. 트리는 **업무 프로젝트 > 폴더(·worktree) > 세션·문서** 세 겹이 되어, 폴더를 눌러 봐야만 알 수 있던 "지금 무엇이 열려 있는지"가 다른 폴더 것까지 한 화면에 들어온다. 종료된 세션, 폴더에 속하지 않는 **도구** 세션, 우측 사이드바에서 연 파일·diff·커밋 그래프·PR이 모두 자기가 나온 폴더 아래에 행으로 붙는다. 세션 행은 예전처럼 상태 색과 읽지 않음 점을 달고, 문서 행의 **✕** 는 그 문서를 닫는다(저장 안 된 파일은 먼저 물어본다)
- **패인 탭 바가 없어지고 그리드가 그 한 줄을 가져간다.** 페이지 이동 **◀ 1/2 ▶** 는 헤더의 레이아웃 타일 옆으로 옮겼다. 화면 밖 페이지로 밀린 패인은 사이드바 행을 눌러 데려온다
- **폴더 이름 옆에 세션 수 칩이 붙는다.** worktree의 세션까지 합한 그 폴더 전체 개수이고, 세션이 하나도 없으면 칩도 뜨지 않는다
- **사이드바 행을 끌어다 놓을 수 있다.** 세션 행이든 문서 행이든 **작업공간1/2/3** 행 위로 끌면 그 작업공간에 담기고, 그리드의 빈 칸이나 가장자리로 끌면 예전 탭 드래그와 똑같이 동작한다. 원본 폴더의 행은 참조로 그대로 남는다
- **세션 우클릭 메뉴에 "작업공간에 추가"가 생겼다.** 작업공간1/2/3을 각자 담고 있는 패인 수와 함께 보여주고, 이미 그 작업공간에 있는 세션이면 비활성이다. 사이드바 행과 패인 헤더 우클릭이 같은 메뉴를 쓴다
- **작업공간 행을 펼치면 담고 있는 패인이 슬롯 순서로 나온다.** 탭 줄이 사라진 뒤 작업공간이 무엇을 담았는지 말하는 유일한 자리다. 행을 누르면 그 패인이 있는 페이지로 이동하고, **✕** 는 그 슬롯만 비워 자동 배치가 다시 쓸 구멍으로 남긴다
- **세션 제거가 확인 팝업 없이 바로 실행된다.** 🗑 을 누르면 "이 세션을 제거할까요?" 다이얼로그를 거치지 않고 그 자리에서 세션이 중지되고 스크롤백이 삭제된다. 패인 헤더의 🗑, 상단 헤더 오른쪽 끝의 🗑, 패인 헤더 **우클릭 → 제거**, 타이틀바 **세션 → 세션 제거** 네 경로가 모두 같다. 되돌릴 수 없다는 사실은 그대로이므로 버튼의 툴팁(`세션 제거 (스크롤백까지 삭제)`)이 유일한 예고가 된다 — 세션을 살려 둔 채 화면에서만 내리려면 옆의 **✕(슬롯 비우기)** 를 쓴다. **worktree 제거·폴더 목록 제거·앱 종료의 확인은 그대로다**: 그쪽은 여러 세션이 한꺼번에 사라지거나 디스크의 변경이 걸린 동작이라 성격이 다르다
- **새로 만든 세션과 새로 연 문서가 작업공간에 자동으로 담긴다.** 지금까지 작업공간1/2/3은 손으로 끌어다 놓은 것만 들어 있었다. 이제 세션을 시작하거나 우측 사이드바에서 파일·diff·커밋 그래프·PR을 열면 그 패인이 작업공간에도 함께 등록된다. **화면은 전환하지 않는다** — 폴더 뷰는 지금 보던 그대로이고, 모아 놓은 화면은 사이드바의 작업공간 행을 눌러 본다
- **채우는 순서는 세 작업공간을 한 선반으로 읽는다.** 작업공간1의 빈 칸부터 채우고, 그 페이지가 차면 작업공간2 → 작업공간3으로 넘어가며, 셋 다 차면 **작업공간1의 2페이지**로 돌아와 다시 여섯 개를 채운다. 한 페이지의 정원은 **그 작업공간이 고른 레이아웃의 칸 수**다 — 기본값 **자동**은 6칸이라 요청대로 6개씩 차고, 작업공간1을 `좌우(2칸)` 로 바꿔 뒀다면 2개만 담고 작업공간2로 넘어간다. 화면에 실제로 보이는 칸만 채운다는 뜻이다
- **손으로 배치한 것은 건드리지 않는다.** 이미 어느 작업공간에든 들어 있는 패인은 다시 담지 않고, 자리를 옮기지도 않는다. 패인을 작업공간에서 **✕** 로 내리면 그 자리는 빈 칸으로 남고 **다음에 만들어지는 패인이 그 구멍을 먼저 쓴다** — 선반이 끝없이 늘어나는 대신 닫힌다
- **작업공간을 보고 있을 때 연 문서는 그 작업공간에 그대로 들어간다.** 이 경우 여는 동작 자체가 보고 있는 격자에 패인을 올리므로 선반은 비켜선다 — 같은 문서가 두 작업공간에 동시에 앉는 일을 막기 위해서다
- 자동 배치에 포함되지 않는 것: **앱 밖에서 생성된 세션**(jk-coding-cli `spawn`, 지연 자동 재개)과 **이미 있던 패인의 사이드바 행 클릭**. 앞의 것은 새 세션인지 되살아난 세션인지 이벤트만으로 가릴 수 없어 제외했고, 뒤의 것은 "여는 것"이 아니라 "보는 것"이라 제외했다
